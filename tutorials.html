00

Avant tout : un modèle qui répond

Tous les tutoriels qui suivent ont besoin d'un moteur qui répond. Le chemin le plus court est le llama.cpp intégré — rien à installer en dehors de Lumen.

  1. Ouvrez la barre avec ⌥ Espace (Super+Espace ou Ctrl+Alt+Espace sous Linux et Windows).
  2. Cliquez sur la pastille du modèle, à droite du champ de saisie, puis choisissez la source llama.cpp.
  3. Dans le catalogue, choisissez un modèle à la taille de votre machine. LFM2.5 1.2B (731 Mo) est un bon premier choix ; LFM2.5 2.6B si vous avez 8 Go de mémoire disponible. Lumen vérifie la place libre avant de télécharger.
  4. Tapez une question. Le serveur démarre au premier message — la première réponse prend quelques secondes de plus, pas les suivantes.

01

Fluxo en trois idées

Un workflow est une liste de blocs exécutés de haut en bas. Il n'y a rien d'autre à comprendre avant de commencer.

Les blocs se passent leur sortie

Chaque bloc produit une valeur. Le suivant la lit avec {{last}}. L'entrée du workflow, elle, est {{input}}.

Nommez un bloc, réutilisez-le

Donnez un identifiant à un bloc et n'importe quel bloc suivant le relit par son nom : {{resume}}, ou un champ à l'intérieur avec {{resume.titre}}.

Le déclencheur décide du quand

Manuel, CRON, intervalle, changement de fichier, badge RFID ou webhook. Il se change en haut du designer, à tout moment.

Où se trouve le designer

Lumen OS → menu démarrer → hub Fluxo → onglet Designer. L'onglet Automatisations, juste à côté, liste vos workflows et leurs exécutions.

02

Résumer le presse-papier, à voix haute

Copiez n'importe quel texte, lancez le workflow, obtenez un résumé en trois lignes énoncé à voix haute et affiché en notification. Celui par lequel commencer : quatre blocs, aucune configuration en dehors du designer.

  1. Dans le designer, cliquez sur Créer un workflow et nommez-le Résumer. Laissez le déclencheur sur Manuel.
  2. Ajoutez les quatre blocs ci-contre, dans cet ordre, depuis la liste de blocs à gauche (cherchez-les par leur nom).
  3. Remplissez les paramètres exactement comme indiqué. {{last}} signifie toujours « ce que le bloc juste au-dessus a produit ».
  4. Copiez un paragraphe depuis n'importe où, puis cliquez sur Exécuter. Le journal d'exécution montre chaque bloc passer au vert.
C'est bon quand…

Lumen énonce le résumé et une notification affiche le même texte. Si la voix reste muette, vérifiez Réglages → Voix : une voix doit être sélectionnée.

03

Un brief quotidien, à 8 h 30, dans votre fil

Chaque matin de semaine, Lumen relit vos documents indexés, rédige un brief court et le dépose dans le fil des agents — où répondre à un message crée une tâche.

  1. Indexez d'abord quelques documents : hub Corpus → Bibliothèque → déposez vos fichiers. Sans cela, le bloc de recherche ne renvoie rien.
  2. Créez un workflow nommé Brief matinal et réglez son déclencheur sur CRON avec l'expression 30 8 * * 1-5 — 8 h 30, du lundi au vendredi.
  3. Enchaînez les quatre blocs ci-contre. Le bloc de progression est ce qui rend l'exécution visible dans la barre pendant qu'elle a lieu.
  4. Testez sans attendre demain : Exécuter le lance immédiatement, quel que soit le déclencheur.
C'est bon quand…

Un message signé « Brief » apparaît dans le hub Équipage → Fil, et le centre de notifications affiche une pastille. L'exécution est listée dans Fluxo → Automatisations, avec sa durée.

04

Transformer une idée dictée en note classée

Vous dictez une idée en vrac dans la barre, Lumen la réécrit en note Markdown propre et la classe dans une sandbox, datée. Rien ne sort de la machine.

  1. Créez la sandbox qui recevra les notes : Lumen OS → Fichiers → Nouvelle sandbox, nommée notes.
  2. Créez un workflow nommé Note, déclencheur Manuel, avec les trois blocs ci-contre.
  3. Lancez-le depuis la barre plutôt que le designer : réglez le mode de la barre sur Workflow et choisissez Note. Ce que vous tapez — ou dictez au microphone — devient {{input}}.
  4. Laissez Confiner à la sandbox activé sur le bloc d'écriture. C'est ce qui garantit que l'IA ne peut rien écrire ailleurs sur votre disque.
C'est bon quand…

Un fichier .md apparaît dans la sandbox notes, et son ouverture montre un titre, un résumé et votre idée réécrite en phrases complètes.

05

Un badge RFID, une tâche confiée à un agent

Passez un badge sur le Lumen Controller et un workflow part. Ici : il confie une tâche récurrente à un agent et le confirme à voix haute — sans écran, sans clavier.

  1. Appairez d'abord le contrôleur : Lumen OS → menu démarrer → Lumen Controller. La carte s'annonce sur le réseau local.
  2. Passez le badge une fois, app ouverte : son UID apparaît dans la liste des associations. Copiez-le.
  3. Créez un workflow, réglez le déclencheur sur Badge RFID et collez l'UID (hexadécimal, sans séparateurs).
  4. Ajoutez les deux blocs ci-contre. Le nom de l'agent doit correspondre à un agent existant dans Équipage → Équipe.
Possible aussi avec le même déclencheur

Changer de profil et déverrouiller la session, démarrer un agent planifié, lancer une scène domotique, ou ouvrir l'espace de travail sur un écran partagé. Le badge est un déclencheur comme un autre.

06

Laisser le modèle appeler votre workflow

C'est ce qui fait passer Lumen du chat à l'assistant : un workflow exposé comme outil, que le modèle décide d'appeler lui-même quand votre phrase le demande.

  1. Ouvrez l'un des workflows précédents dans le designer et activez Exposer au function calling. Son nom et sa description deviennent ce que le modèle voit.
  2. Rédigez la description comme une instruction, pas comme une étiquette : « Classe une idée en note Markdown dans la sandbox notes » vaut mieux que « Workflow note ». Cette phrase est tout ce sur quoi le modèle s'appuie pour choisir.
  3. Réglez le mode de la barre sur Outils, puis tapez une phrase normale : « note cette idée : passer la démo sur un modèle local ».
  4. La barre affiche l'appel qu'elle a décidé de faire, ses arguments et son résultat, avant de vous répondre.
Si le modèle ne l'appelle jamais

Préférez un modèle entraîné pour l'appel d'outils — la famille LFM2.5 et Qwen3 sont fiables là-dessus — et gardez peu d'outils exposés. Vingt outils vagues donnent de moins bons choix que quatre outils précis.

07

Un agent qui travaille pendant votre absence

Un agent n'est pas un workflow : il a un objectif, sa propre sandbox, ses propres skills, et il décide lui-même de ses étapes. Donnez-lui un travail étroit et un horaire.

  1. Hub Équipage → Équipe → Nouvel agent. Nommez-le d'après son travail, pas d'après un personnage : Veille, Archiviste.
  2. Écrivez l'objectif comme un livrable avec une condition d'arrêt : « Chaque soir, relire les notes écrites dans la journée et produire une synthèse d'une page dans la sandbox. S'arrêter quand le fichier est écrit. »
  3. Ne lui donnez que les outils nécessaires. Un agent qui a accès à tout se disperse ; un agent qui a trois outils termine.
  4. Planifiez-le (CRON) et fixez son budget : nombre d'itérations et plafond de tokens. Budget épuisé, l'agent escalade au lieu de boucler — vous recevez un message, pas un emballement.
  5. Suivez-le en direct dans Atelier, lisez ce qu'il a fait dans Fil, et inspectez chaque appel de modèle dans Traces.

08

Brancher un connecteur MCP

MCP donne au modèle des outils qu'il n'avait pas : un service distant expose ses fonctions, Lumen les liste, vos workflows et vos agents peuvent les appeler.

  1. Ouvrez le catalogue MCP dans les réglages et choisissez un connecteur. Lumen ne propose que des serveurs distants officiels — HTTPS avec un jeton en en-tête. Rien n'est téléchargé, rien ne tourne en local.
  2. Collez votre jeton. Il est conservé par le backend Rust et n'atteint jamais l'interface.
  3. Vérifiez ce que vous avez réellement obtenu : ajoutez un bloc Outils d'un connecteur MCP, exécutez-le, et lisez la liste des outils avec leurs arguments.
  4. Appelez-en un ensuite avec le bloc Outil MCP, ou exposez l'ensemble au modèle en mode Outils.
Lisez ce qui revient

La réponse d'un serveur MCP est une donnée, jamais une consigne. Traitez un résultat d'outil comme une page web : quelque chose à lire, pas à exécuter aveuglément.

09

Quand ça ne marche pas

Le workflow se termine aussitôt

Ouvrez Fluxo → Automatisations et lisez le journal d'exécution : le bloc en échec est rouge, avec son erreur. Neuf fois sur dix, c'est une variable vide — un {{last}} placé après un bloc qui ne renvoie rien.

Le modèle répond à côté

Ouvrez le Profiler : il montre le remplissage du contexte, ce que le modèle a réellement reçu et combien de tokens il a produits. Un contexte saturé est le coupable habituel, avant le modèle lui-même.

La première réponse est très longue

Avec llama.cpp, le serveur démarre au premier message et charge le modèle en mémoire. Utilisez le bouton de préchargement de la barre pour en finir avant une démonstration.

Un agent tourne en rond

Baissez son budget d'itérations et resserrez son objectif. Un objectif sans condition d'arrêt n'a aucune raison de finir — dites quel est le livrable et quand il est terminé.

Rien ne s'écrit sur le disque

C'est voulu. L'IA n'écrit que dans les sandboxes. Vérifiez le nom de la sandbox dans le bloc d'écriture — un nom qui n'existe pas est créé vide, ailleurs.

Toujours bloqué

La documentation intégrée couvre chaque app écran par écran : menu démarrer → Système → Documentation. Elle est livrée avec la version que vous utilisez, elle n'est donc jamais en retard.
