Bienvenue

Un environnement de travail avec une IA locale

Lumen se présente comme une barre flottante, une application de discussion ou un bureau avec fenêtres et applications. Assistant, agents et automatisations partagent les mêmes outils ; le Catalogue permet d’installer les applications selon vos besoins.

Des moteurs locaux et un fournisseur distant optionnel
Ollama, llama.cpp embarqué, Apple Foundation Models sur un système compatible ou une API compatible OpenAI. L’intégration Raccourcis Apple reste un chemin distinct. La disponibilité des outils dépend du moteur et du modèle choisis dans les Réglages.

Vos espaces de travail

Équipage gère les agents, messages, traces et diagnostics ; Fluxo construit les automatisations ; Corpus et Prisme organisent documents, recherche RAG et données ; Muse, Opus et Calc servent à écrire et créer ; Tempo regroupe agenda, tâches et Kanban. Le navigateur, l’e-mail, la génération d’images, la voix, les applications métier et les compagnons matériels se configurent séparément.

Local et connecté

L’inférence et les données peuvent rester sur cet appareil. Les fonctions web, API distante, messagerie, synchronisation et compagnon réseau communiquent avec les services choisis. Le Catalogue, les mises à jour et le téléchargement des moteurs et modèles utilisent le réseau. Une fois les composants installés, les fonctions locales peuvent fonctionner hors ligne.

Développement · Sources

Compiler et contribuer

Node.js 22.12+, Rust stable ≥ 1.89, Git, CMake et les outils natifs du système sont nécessaires. Les modèles et moteurs précompilés ne sont pas dans l’export source.

Démarrage

npm ci
npm run tauri dev

Configurer Ollama, ou construire les moteurs locaux avec npm run build:llama et npm run build:whisper. L’inférence nécessite un modèle installé. Le frontend utilise des modules JavaScript natifs ; la livraison prépare un noyau séparé des paquets du Catalogue.

Build par plateforme

macOS
Command Line Tools Xcode et CMake ; npm run build:mac produit l’application et le DMG. Les passerelles Apple nécessitent un SDK compatible. La notarisation utilise les certificats du distributeur.
Windows
Visual Studio Build Tools C++, Windows SDK, WebView2 et CMake ; powershell -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1.
Linux
WebKitGTK 4.1, compilateur C/C++, OpenSSL, libxdo, librsvg, libudev, pkg-config et CMake ; bash scripts/build-linux.sh, sans sudo pour le build.
Raspberry Pi
Système 64 bits, prérequis de scripts/install-prereqs-pi.sh, puis bash scripts/build-pi.sh pour les blocs matériels.

Catalogue et vérification

npm test
npm run eval:orch
npm run build:frontend
npm run apps:package
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked
npm run security:audit

Les tests HTTP nécessitent un port loopback. Le banc d’orchestration utilise un modèle scripté et ne remplace pas les essais avec un vrai modèle. Les étapes détaillées sont dans README.md et CONTRIBUTING.md à la racine des sources.

Export du mainteneur

npm run source:plan montre la sélection et npm run source:sync prépare le dossier public-source/. Sync Hub propose les mêmes opérations dans l’onglet Code source. Le volume de build APFS et les cibles privées restent dans le dossier de travail. L’export ne crée pas de commit et ne publie rien sur Internet.

Les images Gaming/Cosy et MetroCity sans preuve de redistribution jointe sont exclues du miroir public. Les autres ressources tierces gardent leurs licences ; voir THIRD_PARTY_NOTICES.md. Les sources originales sont sous GPL-3.0-or-later.

Bureau · Organisation

Les hubs du bureau

Le bureau ne liste plus une icône par outil. Les applications qui travaillent sur le même objet — un même corpus, une même tâche, un même flux — sont réunies dans un hub : une fenêtre unique, une identité, des onglets. Chaque onglet reste l'application complète que vous connaissez ; c'est le toit qui a changé, pas le contenu.

Comment un hub fonctionne

Une fenêtre
Un hub s'ouvre en une seule fenêtre. La barre du haut porte son nom, sa promesse et ses onglets.
Onglets vivants
Un onglet est chargé la première fois que vous l'ouvrez, puis reste actif en arrière-plan. Revenir dessus ne recharge rien et ne perd aucun travail en cours.
Navigation
Clic sur un onglet, flèches ← → quand la barre d'onglets a le focus, ou ⌘/Ctrl + 1…9. Le bouton de rechargement ne recharge que l'onglet affiché.
Une seule fenêtre par hub
Demander une app déjà ouverte dans un hub — depuis l'orbe, un agent ou la recherche — remet la fenêtre au premier plan et bascule sur le bon onglet, sans jamais dupliquer.
Anciens noms
Les identifiants historiques restent valides partout : workflows, raccourcis. Demander « Notes » ouvre Muse sur l'onglet Notes.

Les dix hubs

Équipage
Votre équipe d'agents de bout en bout : Équipe (créer et régler), Fil (leurs messages et tâches), Traces (appels de modèles, outils, escalades), Profiler (ce que les modèles consomment vraiment).
Fluxo
Du croquis à l'automatisation qui tourne : Automatisations (vos workflows et leurs exécutions) et Designer (composer bloc à bloc).
Prisme
Des données brutes au modèle entraîné : Tables, Analyse, Modèles. Le pipeline complet sans passer d'une app à l'autre.
Corpus
Ce que Lumen sait de vos documents : Bibliothèque (l'index RAG) et Enquête (l'agent qui fouille et rend un rapport sourcé).
Muse
Une idée, quatre façons de la faire grandir : Notes, Carte mentale, Planche visuelle, Canevas créatif.
Tempo
Vos tâches, au Tableau ou à l'Agenda.
Forge
Décrire une app, la générer, la coder : Studio (génération) et Code (édition), sans changer de fenêtre.
Écho
Donner une voix à ce que vous écrivez : Podcast et Voix (essayer et gérer les voix locales).
Arcade
De quoi souffler un peu : Jeux, Aventure, Compagnon.
Opus
Le seul cas où deux apps sont devenues une seule : documents et présentations partagent désormais un éditeur unique, le format étant un simple réglage commutable.

Installation & prérequis

Tout installer en une commande

Un script « tout-en-un » par plateforme met en place ce dont Lumen a besoin : le moteur LLM local Ollama et un modèle par défaut, plus les voix et la dictée locales là où elles existent.

💡

Les scripts sont interactifs (chaque étape demande O/n) et idempotents : relançables sans risque. Ajoutez --yes pour tout installer sans question. Lancez-les depuis le dossier du projet.

Utilisation ou compilation ?

Les scripts ci-dessous installent les moteurs et modèles pour utiliser Lumen. Ils ne compilent pas l’application. Pour construire depuis les sources, consultez la page Compiler et contribuer du sommaire.

macOS

./scripts/setup-macos.sh

Installe Ollama (via Homebrew) et télécharge le modèle par défaut, puis propose Piper local avec les voix FR & EN. Sur macOS, Piper est installé dans un environnement Python isolé car les anciennes archives natives sont incomplètes. Les voix système et la dictée macOS restent disponibles.

Linux (Debian/Ubuntu x86_64)

./scripts/setup-linux.sh

Installe Ollama + le modèle, puis propose les voix locales Piper (avec voix FR & EN) et Kokoro, ainsi que la dictée whisper.cpp.

Raspberry Pi (64-bit)

./scripts/setup-pi.sh

Comme Linux, en arm64. Privilégiez un petit modèle ; pour l'image et les gros modèles, déportez l'inférence sur une autre machine (Réglages → IA → URL). Le service GPIO se configure à part via ./scripts/install-prereqs-pi.sh.

Windows 10/11 x64

powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1

Installe Ollama (via winget) + le modèle, puis propose Piper MIT avec les voix FR & EN. Les voix système Windows et l'app compagnon mobile restent disponibles.

Options communes

--yes
Mode non interactif : installe tout sans poser de question.
LUMEN_MODEL
Modèle Ollama à télécharger. Défaut : liquidai/lfm2.5-350m:latest. Ex. LUMEN_MODEL="qwen2.5:3b" ./scripts/setup-linux.sh.
ⓘ

Piper est disponible sur macOS, Windows x64, Linux et Raspberry Pi. Windows/Linux/Pi utilisent les anciens binaires MIT ; macOS utilise le runtime maintenu GPL-3.0, les archives MIT macOS étant incomplètes. Le choix du moteur et de la voix se fait dans Réglages → Voix et dictée.

☁︎

Besoin d'un modèle cloud ? Aucun script requis : ajoutez une clé API dans Réglages → IA (OpenAI-compatible, Groq, OpenRouter…). Le local reste le mode par défaut.

Guide rapide

Les essentiels

Tout ce qu'il faut savoir pour utiliser Lumen au quotidien, en six fonctionnalités clés.

Poser une question
Tapez dans la barre et appuyez sur Entrée. Lumen répond via le Modèle Apple (local, privé) ou via vos modèles Ollama — au choix dans les Paramètres.
Mode Action
Activez l'éclair : au lieu d'une réponse, Lumen envoie votre demande à un « Routeur d'Actions » qui décide quoi faire et renvoie sa progression en direct.
Heartbeat
Une tâche d'arrière-plan programmée (façon CRON) qui déclenche un raccourci à intervalle régulier : synchro, veille, rappel, ou une vraie boucle d'agent.
Widgets à la volée
En mode Action, vos raccourcis peuvent afficher de vraies cartes (météo, infos système, bourse, rapport…) directement dans la discussion.
Profil & Mémoire
L'onglet Profil dit à Lumen qui vous êtes et comment répondre. La Mémoire partagée (todo, états, stockage) est lisible et écrivable par vos raccourcis.
Compagnon mobile
Pilotez Lumen depuis votre téléphone ou votre tablette, dans le navigateur (même Wi-Fi ou VPN), avec un accès protégé par code TOTP. La voix est gérée par l'appareil.
Telegram
Discutez avec Lumen depuis votre téléphone, hors de chez vous : questions, recherche dans vos documents, workflows, tâches d'agent et images. Aucun port n'est ouvert sur votre machine.
💡

Les boutons d'outils de la barre s'adaptent à la taille choisie (petit / moyen / grand) : les moins utilisés se replient dans un menu « Plus ».

Personnalisation · Avatar

Créer un avatar animé dans Blender

L'orbe peut être remplacé par votre propre personnage 3D. Lumen attend un fichier GLB glTF 2.0 autonome contenant le modèle, les matériaux, les textures, le squelette et toutes ses animations.

ⓘ

Cette convention s'appelle Lumen Avatar Animation Contract v1. Les noms d'animations sont l'interface entre Blender et les états de Lumen : ils sont sensibles à la casse et ne doivent pas recevoir de suffixe comme .001.

La bouche de l'orbe

L'orbe standard peut afficher une bouche animée par la voix : une barre horizontale, taillée comme les yeux, qui s'ouvre au rythme de la parole et se referme au silence. Elle s'active dans Réglages → Avatar → Bouche animée par la voix et reste éteinte par défaut.

Voix locales
Piper et Kokoro produisent un fichier audio : Lumen en calcule l'enveloppe sonore avant la lecture, et la bouche suit la voix réellement prononcée, syllabe par syllabe.
Voix système & Raccourcis
Aucun échantillon n'est accessible : la bouche suit alors une animation de parole synthétique, au rythme d'une voix moyenne.
Avatar GLB
Sans objet. Un modèle 3D personnalisé remplace toutes les couches de l'orbe, y compris les yeux et la bouche : c'est l'animation Lumen_Speaking qui prend le relais.

Contrat des animations

Lumen_Idle
Requise · boucle. L'assistant attend ; utilisez une respiration ou un mouvement discret.
Lumen_Thinking
Requise · boucle. Une réponse est en cours de génération.
Lumen_Speaking
Requise · boucle. Lumen lit sa réponse avec la synthèse vocale.
Lumen_Action
Requise · boucle. Un outil, un workflow Fluxo ou une action est en cours d'exécution.
Lumen_Heartbeat
Optionnelle · une fois. Jouée lors d'un Heartbeat, puis Lumen revient à l'animation courante.

Les quatre clips requis doivent exister, même si certaines animations utilisent provisoirement les mêmes images clés. Lumen sélectionne les clips par leur nom, jamais par leur ordre dans le fichier, et effectue un fondu d'environ 0,22 seconde entre deux états.

Préparer la scène Blender

  1. Placez l'avatar à l'origine, avec Z comme axe vertical et le personnage orienté vers -Y.
  2. Sélectionnez le maillage et l'armature, puis appliquez Object → Apply → Rotation & Scale avec Ctrl+A.
  3. Dans Dope Sheet → Action Editor, créez une Action distincte pour chacun des quatre noms requis. Ajoutez l'Action optionnelle Heartbeat si nécessaire.
  4. Rendez les quatre Actions principales parfaitement bouclables : la dernière pose doit rejoindre naturellement la première.
  5. Poussez chaque Action dans une piste du NLA Editor, ou activez son Fake User, afin qu'aucun clip ne disparaisse lors de l'export.
  6. Utilisez des matériaux Principled BSDF compatibles glTF et vérifiez que toutes les images de texture sont chargées dans Blender.
💡

Les animations peuvent piloter une armature, des Shape Keys ou des transformations d'objets. Lumen recentre et redimensionne automatiquement l'ensemble : aucune taille Blender particulière n'est imposée.

Réglages d'export glTF 2.0

Dans Blender, ouvrez File → Export → glTF 2.0 et utilisez ces valeurs :

Format
glTF Binary (.glb). Le format texte .gltf n'est pas accepté.
Include
Objets visibles, ou Selected Objects si toute la hiérarchie de l'avatar est sélectionnée.
Mesh
Exportez UVs, Normals et Shape Keys lorsque le modèle les utilise.
Armature
Export Deformation Bones Only est recommandé pour ne pas embarquer les contrôleurs du rig.
Animation
Activée, en mode NLA Tracks ou Actions selon la version de Blender.
Sampling
Activez Always Sample Animations si le rig utilise des contraintes ou des drivers.
⚠︎

Le fichier final doit faire moins de 25 Mo. Un GLB standard non compressé est le choix le plus portable ; n'utilisez Draco ou Meshopt qu'après avoir testé le fichier dans Lumen.

Réglages propres au GLB

Lumière ambiante
Le curseur Lumière ambiante du GLB, dans Paramètres → Avatar, ajuste la luminosité du personnage de 0 à 250 %.
Position
Le GLB reste fixe. Lumen n'ajoute ni flottement ni rebond ; seuls les mouvements créés dans les animations Blender sont joués.
Séparation de l'orbe
La lumière GLB, la position fixe et le retrait du cercle givé ne modifient pas l'orbe. Ses effets d'origine reviennent automatiquement lorsque le type Orbe Lumen est choisi.

Importer dans Lumen

  1. Ouvrez Paramètres → Avatar.
  2. Dans Type d'avatar, choisissez GLB personnalisé.
  3. Cliquez sur Choisir un GLB… et sélectionnez le fichier exporté.
  4. Attendez le message contrat Lumen valide ✓, puis enregistrez les paramètres.

La validation contrôle le conteneur GLB, la version glTF 2.0 et les quatre noms requis. Un fichier refusé ne remplace jamais l'avatar précédent. Le fichier accepté reste stocké localement dans les données de Lumen.

Résoudre les problèmes courants

Clip manquant
Vérifiez le nom de l'Action et de la piste NLA. Retirez les espaces et les suffixes automatiques comme .001.
Une seule animation
Poussez chaque Action dans une piste NLA non muette, ou activez son Fake User, puis exportez en mode NLA Tracks.
Modèle gris
Reconnectez les textures à un Principled BSDF et réexportez en GLB afin que les images soient embarquées.
Mauvaise orientation
Corrigez la rotation en mode Object, appliquez Rotation & Scale, puis réexportez.
Animation saccadée
Vérifiez la continuité entre la dernière et la première pose, puis activez l'échantillonnage des animations à l'export.
✓

Checklist finale : un seul fichier .glb, toutes les textures visibles sur une autre machine, quatre clips requis au nom exact, boucles fluides, aucun objet de travail inutile et moins de 25 Mo.

Module · Agents

Agents autonomes

Un agent est une petite boucle autonome qui prend des tâches dans sa todo list et les traite à l'aide de ses skills, en écrivant ses résultats dans une sandbox confinée.

ⓘ

Les agents reposent sur le function calling d'Ollama. Ils ne sont donc disponibles qu'en source Ollama Ollama — masqués en mode Apple Intelligence.

Anatomie d'un agent

Instruction
Le « system prompt » de l'agent : son rôle, ses objectifs, ses règles. Il pilote la boucle et le choix des skills.
Modèle dédié
Modèle Ollama propre à l'agent (vide = modèle global). Doit supporter les outils : qwen2.5, llama3.1…
URL Ollama
Serveur Ollama dédié à cet agent (vide = URL globale des réglages).
Contexte (num_ctx)
Taille de la fenêtre de contexte. Plus grande = plus de mémoire utilisée.
Sandbox
Espace fichiers isolé où l'agent écrit ses résultats (dossier journal/). Bouton « 📂 Ouvrir » pour l'inspecter.
Skills
Des workflows Fluxo exposés comme outils : le modèle les appelle à la demande pendant la boucle.
Outils de Lumen
Les capacités natives de l'application, cochées une par une : maison connectée, recherche web, documents, bases de données, mémoire, rappels, messagerie. Rien n'est exposé par défaut, et les outils qui sortent de la machine (recherche et lecture web) demandent une approbation.
Tâches
Une todo list. Chaque tâche peut porter une date d'exécution programmée.
Planification
Constructeur de récurrence (minutes, heures, jours de semaine, jours du mois, dernier jour du mois) ou expression CRON écrite à la main, avec aperçu des prochaines exécutions. Les heures sont en UTC, l'aperçu les convertit dans ton fuseau. Vide = uniquement manuel.

Le cycle de travail (un tick)

  1. L'agent sélectionne la prochaine tâche en attente et échue (voir dates ci-dessous).
  2. Guidé par son instruction, le modèle raisonne et appelle ses skills (workflows Fluxo) comme des outils, autant de fois que nécessaire.
  3. Le résultat est écrit dans la sandbox de l'agent (confiné, quota respecté), typiquement sous journal/.
  4. La tâche est marquée comme faite ; l'activité (compte rendu + appels de skills) est consignée et persistée.

Tâches programmées (dates)

Une tâche sans date est disponible immédiatement. Une tâche avec une date n'est visible par l'agent qu'à partir de ce jour : tant que l'échéance est dans le futur, l'agent l'ignore (badge 🔒). Le jour venu — ou si la date est passée — elle devient accessible (badge vert).

📅

Le bouton Calendrier de la page d'un agent affiche une vue mensuelle de toutes les tâches datées : pastille par tâche, jour courant surligné, survol pour le détail.

Déclencher un agent

  • Manuellement — bouton « Lancer maintenant » dans l'éditeur.
  • Par planification — l'expression CRON de l'agent (nécessite l'interrupteur activé).
  • Depuis Fluxo — le bloc run_agent traite la prochaine tâche ; agent_add_task ajoute une tâche. Idéal couplé au workflow Heartbeat.
⚠︎

Supprimer un agent retire sa configuration mais ne touche pas à sa sandbox : les fichiers produits restent disponibles dans l'explorateur de sandboxes.

Module · Sandbox

Sandboxes fichiers

Chaque sandbox est un dossier isolé, limité en taille, où agents et workflows peuvent créer et analyser des fichiers sans jamais toucher au reste de votre disque.

Le confinement, concrètement

Toutes les opérations fichiers sont cantonnées à la racine de la sandbox. Le moteur :

  • refuse les composants de chemin dangereux (.., chemins absolus) ;
  • canonicalise l'ancêtre le plus proche et vérifie qu'il reste sous la racine (défense contre les symlinks d'évasion) ;
  • applique un quota de taille par sandbox, qui empêche de remplir le disque hôte.
⚠︎

C'est une sandbox applicative, pas une isolation noyau. Elle protège contre un agent qui dérape ou un fichier piégé — à condition de ne pas exposer d'exécution de commandes ni de réseau arbitraire au périmètre de l'agent.

L'explorateur

Ouvrez-le depuis les Paramètres → onglet Agents → « Ouvrir les sandboxes », ou depuis un agent via « 📂 Ouvrir ». Il offre :

Vues
Grille ou liste, tri par nom / type / taille.
Fichiers & dossiers
Créer, renommer, supprimer, importer (glisser-déposer) et exporter.
Aperçu
Panneau d'aperçu redimensionnable : texte, images, et autres visionneuses intégrées.
Versions
Instantanés (snapshots) d'un fichier pour comparer ou revenir en arrière.
Launchpad
Lance les petites applications HTML déposées dans la sandbox.
Quota
Jauge d'usage en bas ; la taille maximale est ajustable par sandbox.
Analyse IA
Sélectionnez un ou plusieurs fichiers (Cmd/Ctrl+clic) pour les faire analyser par le modèle.

Accès depuis les workflows

Les blocs read_file et write_file de Fluxo savent viser une sandbox :

  • en renseignant explicitement le champ « Sandbox » (nom) → chemin relatif, confiné, quota respecté ;
  • via l'option « Confiner à la sandbox » → utilise la sandbox de l'agent courant ;
  • sinon, chemin libre (hors périmètre agent).
✓

Pour les agents, les deux modes sont utilisables. Le champ Sandbox (nom) passe par le pont Lumen et conserve le quota/versioning de la sandbox. L'option Confiner à la sandbox est plus directe : elle reste confinée au dossier de l'agent, mais elle écrit au niveau filesystem.

App · Canevas créatif

Explorer des idées en arborescence

Le Canevas créatif est un espace infini où chaque bloc peut produire une suite : texte, image, charte, visuel de marque, jingle ou analyse d'image. Les liens entre blocs transmettent le contexte, pour construire une piste créative étape par étape.

Créer et relier des blocs

  1. Double-cliquez dans le vide ou utilisez « Nouveau point de départ » pour créer une première idée.
  2. Tirez la pastille de sortie d'un bloc vers le vide pour ouvrir la boîte de prompt et choisir le type de génération.
  3. Tirez un lien vers un bloc existant pour l'ajouter comme parent : la prochaine régénération fusionnera les informations reliées.
  4. Utilisez l'historique d'un bloc pour revenir à une variante, puis régénérez pour créer une nouvelle version.

Types de blocs

Texte
Génération rédactionnelle à partir du prompt et des ancêtres reliés.
Image
Génération d'image local-first : Bonsai ou Ollama en local si disponible, cloud configuré en secours. Le sélecteur « Image » de la barre permet aussi d'imposer un moteur.
Charte
Palette, intention et typographies réutilisées par les visuels enfants.
Visuel
Mockup de marque qui intègre la charte et l'image parent reliées. Export natif vers .lumenpages ou .lumenkey.
Analyse
Extraction vision multimodale : reliez une image, puis demandez description, couleurs, composition ou direction artistique.
Jingle
Texte court prêt à être lu par la synthèse vocale Piper/Kokoro via le bouton d'écoute.

Stockage et exports

Chaque projet vit dans une sandbox dédiée Canevas : le fichier project.json garde les prompts, positions, liens et historiques ; les images et polices sont stockées à côté, sous forme de fichiers.

✓

Depuis une carte Visuel, les boutons Page et Deck créent des fichiers prêts pour Lumen Documents et Lumen Présentations dans le dossier exports/ du projet.

App · Connaissances

Base documentaire RAG locale

Connaissances indexe vos documents pour que Lumen, les agents et les workflows Fluxo puissent retrouver les bons extraits au moment de répondre. Import, encodage, recherche et suppression se font sur votre machine.

Importer des contenus

Glisser-déposer
Déposez PDF, DOCX, texte, Markdown, CSV, JSON, HTML, logs ou fichiers de code dans la zone d'import.
Fichier
Le bouton « Choisir un fichier » accepte plusieurs fichiers à la fois.
Texte collé
Un panneau dédié permet d'indexer une note ou un contenu rapide sans créer de fichier.
Volume indexé
Chaque document affiche son nombre d'extraits et son volume de texte. C'est le moyen de vérifier qu'un PDF est passé en entier : 3 000 caractères pour quarante pages trahissent une extraction partielle.
ⓘ

Un PDF scanné n'a aucune couche texte : Lumen refuse l'import plutôt que d'indexer un document creux, car il n'y a pas de reconnaissance optique. L'ingestion est atomique — un document est indexé en entier ou pas du tout.

L'encodeur (embeddings)

C'est le modèle qui transforme un extrait en vecteur. Il se choisit dans l'app ou dans Paramètres, Modèles, Embeddings, et le même choix sert à l'indexation et à la recherche.

Liquid AI LFM2.5 Embedding 350M
Léger et rapide, 1024 dimensions, fenêtre de 512 jetons. Téléchargé à la demande et servi en local par un second serveur, sur un port privé.
Qwen3 Embedding 0.6B
Plus lourd, plus fin sur les corpus multilingues.
Automatique
Suit la source d'IA : Ollama encode avec son propre modèle, une API compatible OpenAI avec le sien. Sans Ollama installé, Lumen retombe sur un encodeur local plutôt que d'échouer.
ⓘ

Chaque famille d'encodeurs attend ses propres préfixes de tâche, et Lumen les applique. Les oublier ne provoque aucune erreur : la pertinence s'effondre en silence. C'est pourquoi l'index mémorise avec quel modèle il a été construit.

Découpage des documents

Le préréglage s'applique aux prochains imports. Choisissez selon le type de contenu :

Petit
Environ 500 caractères. Extraits courts, réponses précises : questions-réponses, fiches, annuaires, notes très structurées.
Moyen
Environ 1 000 caractères. Équilibre par défaut : assez de contexte sans diluer la recherche.
Grand
Environ 1 800 caractères. Pour les rapports et la prose longue, où le contexte autour de l'extrait compte.
⚠︎

Le préréglage Grand dépasse la fenêtre de 512 jetons de LFM2.5 Embedding : la fin de l'extrait ne participerait pas au vecteur. Avec cet encodeur, restez sur Petit ou Moyen ; le texte, lui, reste entier dans la recherche par mot-clé.

Comment la recherche fonctionne

Deux moteurs travaillent en parallèle sur chaque question, puis leurs classements sont fusionnés. Un extrait trouvé par les deux voies passe devant.

Par mot-clé
Index plein texte : imbattable sur les noms propres, les références et les termes exacts du document. Le nom du fichier est indexé avec le texte, et découpé en mots : « de quoi parle RESTAPIforBlackmagicCameras.pdf ? » trouve le bon document, « blackmagic » aussi.
Mots vides
« de », « quoi », « parle » sont écartés de la recherche par mot-clé : ils correspondent à tous les extraits du corpus et noieraient les vrais candidats. Sauf si la question n'est faite que de ceux-là, auquel cas mieux vaut chercher avec eux que pas du tout.
Un document ne monopolise pas
Quand plusieurs documents répondent, chacun a un quota dans la liste rendue. Sans cela, un fichier dont tous les extraits contiennent un mot courant de la question raflait toutes les places, et la base semblait se résumer à lui.
Par le sens
Similarité vectorielle : retrouve une reformulation qui ne partage aucun mot avec la question.
Score
Le pourcentage affiché est la similarité de l'extrait avec la question. Son échelle dépend de l'encodeur : 25 % avec LFM2.5 peut valoir 70 % avec un autre modèle. La pertinence se juge donc par rapport au meilleur extrait de la même recherche, jamais sur un seuil fixe.
Jamais vide
Tant qu'il existe des candidats, la recherche rend les meilleurs, même faibles. Une liste vide laisserait croire que le document ne contient pas la réponse.

Réindexer

Réindexer ré-encode les extraits déjà stockés, sans réimporter les fichiers. Le bouton apparaît de lui-même quand c'est nécessaire :

Changement d'encodeur
Les vecteurs d'un modèle ne sont pas comparables à ceux d'un autre. Tant que l'index n'est pas reconstruit, les nouveaux imports sont refusés.
Index d'une version antérieure
Métrique ou préfixes de tâche différents de ceux en vigueur : la recherche compare alors des vecteurs qui ne se correspondent plus.

Utilisation par l'IA

Assistant
Le mode Documents de la barre interroge la base à chaque question. Dans les autres modes, l'IA peut la consulter par l'outil de recherche documentaire.
Fluxo
Le bloc « Rechercher dans les connaissances » injecte des extraits RAG dans un workflow.
Agents
Un agent peut consulter la base pour traiter une tâche sans embarquer tout un dossier dans son prompt.
Enquête, Podcast, Navigateur, Telegram
La même base sert aux rapports sourcés, aux épisodes audio, à l'enregistrement d'une page web et aux questions posées depuis le téléphone.

Test de recherche

Le panneau de droite montre exactement ce que l'IA récupérera pour une question donnée, avec le score de chaque extrait et une pastille sur ceux trouvés par mot-clé. C'est l'outil à utiliser avant de conclure que le RAG ne trouve rien : si le test remonte les bons passages, le problème est dans la formulation de la question, pas dans l'index.

Bureau · Assistant

Un assistant dans chaque application

Les applications du bureau ne se pilotent plus seulement à la souris : chacune porte un bouton Assistant ancré au bord droit de sa fenêtre. Il ouvre un volet de conversation qui agit à l'intérieur de l'app — créer, classer, corriger, résumer — en appelant les outils que cette app déclare, jamais en devinant à votre place.

Ouvrir le volet

Bouton latéral
La poignée « Assistant » est toujours au même endroit, quelle que soit l'application : bord droit de la fenêtre. Un clic déplie le volet, un autre le replie.
Raccourci
⌘J (macOS) ou Ctrl+J ouvre et referme le volet. Échap depuis le champ de saisie le replie.
Mémoire d'ouverture
L'état déplié/replié est retenu par application : le volet vous attend ouvert là où vous vous en servez, et reste discret ailleurs.
Suggestions
Sous le fil, chaque app propose quelques demandes typiques. Un clic les envoie telles quelles — utile pour découvrir ce que l'assistant sait faire ici.

Où il est disponible

Le volet est le même partout ; ce sont ses outils qui changent d'une application à l'autre.

Muse
Notes, Carte, Planche.
Tempo
Tableau, Agenda.
Prisme
Tables, Analyse.
Corpus & Écho
Bibliothèque, Podcast.
Apps autonomes
Mémoire, Fil, Budget, Studio musical, Domotique, Automatisations.

Comment il agit

Une demande n'est pas transformée en texte décoratif : elle est exécutée. L'assistant reçoit l'état courant de l'application et la liste des actions autorisées, puis enchaîne ces actions jusqu'à répondre.

Outils déclarés
Chaque application publie ses propres actions (créer une note, déplacer une carte, ajouter une ligne, programmer un rappel…). L'assistant ne peut rien faire d'autre : hors de cette liste, il le dit au lieu d'inventer.
Contexte
L'état visible de l'app est joint à la demande — ce qui existe déjà, sous quels identifiants — pour que l'IA lise avant de modifier.
Plusieurs étapes
Jusqu'à huit tours d'outils par demande, puis un résumé court de ce qui a réellement été fait. Chaque étape s'affiche en direct dans le fil.
Suite de la conversation
Les six derniers échanges sont renvoyés au modèle : « et range-les par thème » se comprend sans tout réécrire. Le bouton ⟲ efface le fil et repart de zéro.
Backend
Le volet suit le backend actif de Lumen — Ollama, llama.cpp, LiteRT ou API compatible OpenAI. Aucun réglage propre à l'app.

Jetons et traçabilité

Le volet consomme des jetons comme la barre principale, et il est compté comme elle.

Compteur du jour
Chaque tour du volet s'ajoute au compteur de jetons du bureau (prompt + génération), y compris les tours intermédiaires d'appel d'outils.
Profiler
Les appels apparaissent sous la source assistant:<app> — on voit donc quelle application a coûté quoi, avec les outils présentés et les durées.
Journal LLM
Le même enregistrement alimente le journal des agissements : modèle utilisé, jetons d'entrée et de sortie, application d'origine.
Backend API
Les réponses au format OpenAI (usage) sont comptées comme celles au format Ollama : le choix du backend ne change plus le total affiché.
App · Navigateur

Naviguer, lire, analyser

Le Navigateur n'essaie pas d'être Chrome. C'est un outil de lecture et d'analyse : la page est récupérée par le backend de Lumen, présentée dans une vue lecture débarrassée du superflu, et le même contenu alimente directement l'IA — résumé, questions, traduction, enregistrement dans Corpus.

Deux vues

Lecture
La vue par défaut, et la seule qui marche partout. La commande Rust web_fetch récupère la page — ce qui contourne le CORS et l'interdiction d'iframe — puis en extrait le contenu principal, rendu en Markdown avec titres, liens et images. Aucun code du site n'est exécuté.
Live
Le site réel dans une iframe, avec son JavaScript. Beaucoup de sites la refusent par en-tête (X-Frame-Options, frame-ancestors) et resteront blancs. Un avertissement s'affiche avant la première activation.
Ce que la vue live ne fait pas
Le site est isolé par origine : il n'a aucun accès à Lumen, à l'API Tauri ni à vos fichiers. En contrepartie il n'y a ni session, ni cookies persistants — on ne se connecte pas à un compte depuis le Navigateur.

Extraction du contenu

Repérer le corps d'un article est ce qui décide de la qualité de tout le reste : ce que vous lisez, mais aussi ce que le modèle reçoit. Le backend note les conteneurs de la page — beaucoup de texte, peu de liens — et resserre vers le bloc le plus dense, plutôt que de retirer aveuglément menus et pieds de page.

Pourquoi c'est important
Le contenu envoyé au modèle est plafonné (≈ 40 000 caractères). Si cette fenêtre est occupée par une liste de langues ou un méga-menu, le résumé porte sur le décor et non sur l'article.
Pages atypiques
Quand aucun bloc ne se détache — résultats de recherche, pages entièrement faites de liens — le texte complet est conservé plutôt qu'amputé.
PDF
Un PDF est reconnu par son en-tête ou sa signature, et son texte est extrait pour la vue lecture comme pour l'IA. La vue live n'est alors pas proposée.
Cache
Les pages récemment ouvertes sont gardées cinq minutes en mémoire : retour, avance et relance d'une action IA sont instantanés et ne retéléchargent rien. Le bouton Recharger court-circuite ce cache.

Le volet IA

Il travaille sur le texte réellement extrait de la page affichée, jamais sur une capture ni sur une supposition.

Résumer · Points clés
Un résumé court ou une liste des informations essentielles, chiffres compris.
Traduire
Traduction du contenu principal dans la langue choisie, sans commentaire.
Questions
L'IA répond en s'appuyant sur la page seule, et le dit quand l'information n'y figure pas.
Enregistrer dans Connaissances
La page rejoint l'index RAG du hub Corpus, avec son URL comme source — elle devient interrogeable hors ligne, par l'assistant comme par les agents.
Contexte du modèle
Avec llama.cpp, le texte est resserré autour du début et de la fin de la page pour tenir dans la fenêtre configurée. Un message explicite invite à augmenter la taille du contexte si elle reste trop petite.

Réglages

Moteur de recherche
DuckDuckGo, Wikipédia ou Marginalia. Les trois servent des résultats lisibles sans exécuter de JavaScript — un moteur qui l'exige rendrait une page vide en vue lecture.
Taille du texte
Les boutons A− / A+ ajustent la vue lecture ; le réglage est conservé.
Ouvrir à l'extérieur
Pour tout ce que la vue lecture ne couvre pas — connexion à un compte, application web, achat — la page s'ouvre dans le navigateur du système.
Prise en main

Catalogue — tout ce qui s'installe dans Lumen

Un seul écran pour ajouter des capacités à Lumen : modèles de langage, voix, workflows Fluxo et avatars 3D. Rien n'est payant et rien n'est téléchargé tant que vous ne cliquez pas sur « Installer ».

ⓘ

Cet écran s'appelait « Market ». Le nom a changé pour ce qu'il est : une liste de ce que vous pouvez installer, pas une boutique.

Les quatre rayons

Modèles
Modèles au format GGUF, exécutés par llama.cpp sur votre machine. Chaque fiche annonce son palier (léger, équilibré, puissant), sa taille sur le disque et ses aptitudes : vision, code, raisonnement, multilingue, appel d'outils.
Voix
Voix Piper et Kokoro pour la synthèse vocale. Une voix installée devient choisissable partout : lecture des réponses, blocs Fluxo, podcast.
Workflows
Automatisations Fluxo prêtes à l'emploi. Elles arrivent dans le designer, où elles restent modifiables comme les vôtres.
Avatars 3D
Fichiers GLB qui donnent un corps à Lumen sur le bureau, en remplacement de l'orbe.

Choisir un modèle sans se tromper

Le critère décisif n'est pas la qualité annoncée mais la mémoire disponible : un modèle qui ne tient pas en RAM ne tourne pas, ou si lentement que la réponse arrive après que vous avez renoncé. Les paliers sont là pour ça.

Léger
Tient sur une machine ordinaire et répond vite. C'est le bon choix pour la barre, le routage et les tâches courtes.
Équilibré
Le compromis habituel : assez de finesse pour rédiger et raisonner, sans monopoliser la machine.
Puissant
Pour les tâches longues et les agents. Exige beaucoup de mémoire, et ralentit tout le reste pendant qu'il travaille.
Appel d'outils
Le badge « outils » signale les modèles qui savent appeler les capacités de Lumen. Sans lui, un agent ne pourra rien faire d'autre que parler.

D'où viennent les listes

Trois sources s'additionnent, elles ne se remplacent jamais :

Liste embarquée
Livrée avec l'application. Toujours disponible, même sans connexion.
Liste officielle Lumen
Publiée dans le dépôt du projet et relue au démarrage : de nouveaux modèles apparaissent sans nouvelle version de l'app. Injoignable, elle est simplement ignorée.
Votre manifeste
L'URL d'un fichier JSON que vous hébergez, pour vos propres modèles ou ceux de votre organisation. Le format attendu est affiché dans l'onglet Sources.

Ce qui part sur le réseau

Consulter le Catalogue lit les listes ; installer télécharge le fichier depuis l'hébergeur indiqué sur la fiche (Hugging Face pour l'essentiel des modèles et des voix). Aucune inscription, aucun compte, aucune télémétrie : Lumen ne signale pas ce que vous installez.

ⓘ

Un téléchargement interrompu ne laisse pas de modèle à moitié installé : le fichier n'est pris en compte qu'une fois complet. Relancer l'installation reprend proprement.

Centre & fichiers

Recherche web

C'est la seule capacité de Lumen qui envoie quelque chose hors de votre machine. Elle est donc désactivée par défaut, activée en deux temps, et réglable dans le détail : moteurs, profondeur, domaines autorisés. Réglages › Boîte à outils.

ⓘ

Deux garde-fous ne sont jamais négociables, quels que soient vos réglages : http(s) uniquement, et aucune adresse locale ou privée. Lumen pilote des objets sur votre réseau : sans ce blocage, une page piégée pourrait souffler au modèle d'aller « lire » l'adresse d'un relais domotique.

Deux outils, deux niveaux d'exposition

Rechercher
Envoie la requête à un moteur et rend les meilleurs résultats : titre, URL, extrait.
Lire une page
Récupère le texte d'une page dont l'URL vient d'une recherche. C'est l'option la plus exposée aux textes piégés : une page entière offre bien plus de place pour glisser des consignes qu'un extrait de deux lignes. Une liste de domaines autorisés la rend nettement plus sûre.

Les moteurs

Aucun n'exige de clé ni de compte : Lumen lit la page de résultats comme le ferait un navigateur.

DuckDuckGo
Version HTML allégée, pensée pour être lue par un programme. Le choix par défaut.
Brave Search
Index indépendant, ni Google ni Bing.
Mojeek
Petit index britannique, très tolérant aux robots : le dernier recours quand les autres refusent.
Wikipédia
Recherche encyclopédique seule : la requête ne quitte pas Wikimédia.
SearXNG ou moteur personnalisé
Votre propre instance, ou n'importe quelle page de résultats : indiquez une URL contenant {query}.

Ce qui rend une réponse fiable

Repli entre moteurs
Si le moteur choisi ne rend rien d'exploitable — limite de débit, page modifiée — Lumen réessaie avec les autres moteurs généralistes, et vous dit lequel a répondu. Le repli ne s'applique jamais à Wikipédia ni à une instance privée : votre requête ne part pas vers un tiers que vous n'avez pas choisi.
Résultats lus automatiquement
Après la recherche, Lumen ouvre les premiers résultats et donne leur contenu au modèle. C'est le réglage qui change tout : sans lui, le modèle ne voit que des titres et comble le reste avec ce qu'il croit savoir — donc avec des informations périmées.
Filtre de récence
Le modèle peut restreindre la recherche au jour, à la semaine, au mois ou à l'année écoulés. Il s'en sert de lui-même sur une question d'actualité, quand le moteur le permet.
Résultats par site
Un plafond par domaine empêche qu'un seul site occupe toute la liste et donne au modèle un point de vue unique, présenté comme un consensus.
Pages parcourues
Au-delà de la première page de résultats pour les recherches pointues. Chaque page est une requête de plus.
Exécution du JavaScript
Beaucoup de sites livrent une page vide que leur script remplit ensuite. Lumen recharge alors ces pages dans une fenêtre invisible pour en lire le contenu réel. La page s'exécute vraiment : à laisser désactivé si vous lisez des sites peu sûrs.

Garder la main

Domaines autorisés
Si cette liste n'est pas vide, l'IA ne peut atteindre aucun autre domaine. C'est le réglage le plus efficace pour rendre la lecture de pages sûre.
Domaines exclus
L'inverse : tout est permis sauf ce que vous nommez.
Contenu marqué comme extérieur
Résultats et pages arrivent au modèle précédés d'un avertissement : ce sont des informations à évaluer et à citer, jamais des instructions à suivre. Un texte bien classé dans un moteur est un vecteur d'injection à part entière.
Côté agents
Un agent ne voit ces outils que s'ils sont cochés sur sa fiche, et la recherche compte comme un effet extérieur : elle demande une approbation avec la politique par défaut.
ⓘ

La requête part telle que le modèle l'a écrite. Rappelez-lui, si le sujet est sensible, de n'y mettre que des mots-clés : le contenu privé de la conversation n'a rien à faire dans une barre de recherche.

App · Relia

Relia — du premier contact à la facture électronique

Relia est le CRM de Lumen, assisté par l'IA : articles et stock, clients, devis, factures. Un devis accepté devient une facture en un clic — et c'est cette bascule qui débite le stock. Les factures sortent au format Factur-X, celui qu'attend la facturation électronique française obligatoire depuis le 1ᵉʳ septembre 2026. Rien n'est enfermé dans l'app : tout vit dans une base SQLite que les autres applications de Lumen savent lire.

Vos données restent des tables

L'app ne tient pas un stockage privé. Elle crée une base ERP dans les Bases de données de Prisme et y écrit huit tables typées : Société, Articles, Clients, Devis, Lignes devis, Factures, Lignes facture, Mouvements stock.

Analyse
Prisme · Analyse ouvre ces tables comme n'importe quelle source : chiffre d'affaires par mois, panier moyen, rotation des articles.
Questions en français
Le NL→SQL des Bases de données interroge la base ERP directement — « quel client a le plus commandé cette année ? » — en lecture seule.
Agents & Fluxo
Un workflow ou un agent peut lire l'encours, relancer un impayé, ou déclencher un réapprovisionnement à partir des mêmes lignes.
Migration douce
Une colonne ajoutée par une mise à jour de Lumen apparaît sur les bases existantes au démarrage suivant, sans toucher aux données déjà saisies.

Articles & stock

Fiche article
Référence, désignation, catégorie, unité (les unités sont celles de la nomenclature UN/ECE reprise dans le XML), prix HT, taux de TVA, coût d'achat, stock et seuil d'alerte. Les taux proposés couvrent la métropole (20, 10, 5,5, 2,1 %) et le taux normal des départements d'outre-mer (8,5 %).
Suivi optionnel
Une prestation ne se stocke pas : l'option « Suivi stock » décide si l'article est décrémenté à la facturation.
Mouvements tracés
Chaque entrée et chaque sortie laisse une ligne datée avec son motif, son document d'origine et le stock résultant. Un stock qui bouge sans explication est un stock que personne ne sait justifier trois mois plus tard.
Alertes
Le tableau de bord liste les articles passés sous leur seuil, et le compteur reste visible tant qu'ils y sont.

Tags & catégories

Passé quelques dizaines d'articles ou de clients, la recherche par nom ne suffit plus. Les tags donnent une seconde entrée : ils se posent sur les articles, les clients, les devis et les factures, et se cumulent.

Saisie par jetons
Tapez, puis Entrée, virgule ou Tab : le tag devient un jeton. Retour arrière sur un champ vide retire le dernier. La croix d'un jeton le supprime.
Autocomplétion
La liste propose les tags déjà employés, les plus fréquents en tête. C'est ce qui évite la dérive qui rend les tags inutiles : « client-fidele » et « Client Fidèle » côte à côte ne filtrent plus rien.
Filtrer
Sous la barre de recherche de chaque liste, les tags de la vue deviennent des pastilles cliquables. Plusieurs pastilles se cumulent : seules les fiches portant tous les tags choisis restent affichées.
Catégories d'articles
Le champ Catégorie s'autocomplète lui aussi sur les catégories existantes — une catégorie par article, là où les tags sont multiples.
Côté données
Les tags sont stockés en clair dans une colonne Tags (« a, b, c ») : ils restent donc filtrables en SQL depuis Prisme, et l'assistant les lit comme le reste.
Héritage
Les tags d'un devis suivent la facture qui en découle : un tag « chantier-2026 » posé une fois se retrouve des deux côtés.

Devis, puis facture

Le devis et la facture partagent le même éditeur : lignes tirées du catalogue ou saisies librement, remise par ligne et remise globale, calcul en direct.

Numérotation
Séquentielle et continue par année (D2026-0001, F2026-0001), calculée sur les documents existants : une suppression ne crée pas de trou dans la suite suivante, ce qu'exige l'administration fiscale.
Bascule en facture
« Basculer en facture » copie les lignes, lie les deux documents, passe le devis en « Facturé » et débite le stock des articles suivis. L'échéance est déduite des conditions de paiement du client ou, à défaut, de celles de la société.
Un seul débit
Le débit est garanti unique : la présence d'un mouvement portant le numéro de la facture empêche un second passage. Un stock qui deviendrait négatif est signalé plutôt que corrigé en silence.
Règlements
Un montant encaissé fait passer la facture en « Partiellement payée » puis « Payée » ; le reste dû alimente l'encours et la liste des retards.
Avoirs
Le type de document (facture, avoir, facture rectificative, acompte) suit les codes EN 16931. Un avoir doit référencer la facture d'origine — le contrôle est bloquant.

Facturation électronique : ce que Lumen produit

Depuis le 1ᵉʳ septembre 2026, toute entreprise assujettie à la TVA en France doit pouvoir recevoir une facture électronique ; l'obligation d'émettre s'applique aux grandes entreprises et aux ETI à cette date, puis aux PME et TPE au 1ᵉʳ septembre 2027. Les échanges passent par une plateforme agréée (PDP), et le format doit appartenir au socle commun.

Factur-X
Le PDF exporté embarque le fichier factur-x.xml comme pièce jointe, déclarée en représentation alternative du document et annoncée dans les métadonnées XMP : un même fichier se lit à l'œil et se traite par machine.
XML CII, profil EN 16931
Syntaxe CII D16B, profil « EN 16931 » : lignes, prix bruts et nets, quantités avec code d'unité, ventilation de TVA par taux et par catégorie, conditions et date d'échéance, coordonnées bancaires, références de commande et de devis.
Profil déclaré
Le champ « Profil Factur-X » de Société & conformité (EN 16931, BASIC ou EXTENDED) est repris dans les métadonnées du PDF. Le XML produit suit toujours le profil EN 16931, qui est le socle attendu : ne changez ce champ que si votre plateforme réclame explicitement une autre déclaration.
Export du XML seul
Le XML est aussi exportable seul, pour un dépôt direct sur votre plateforme ou sur Chorus Pro pour un client public.
Où vont les fichiers
Dans la sandbox et le dossier que vous choisissez — jamais directement sur le disque de la machine.

Les mentions que l'app impose

Avant tout export, la facture passe une série de contrôles. Les points bloquants arrêtent l'export : une plateforme les rejetterait de toute façon.

Identité de l'émetteur
Raison sociale, forme juridique et capital, adresse, SIREN et SIRET, RCS, code APE, numéro de TVA intracommunautaire — sauf franchise en base, qui porte alors la mention « TVA non applicable, article 293 B du CGI ».
SIREN du client
Nouvelle mention obligatoire depuis le 1ᵉʳ septembre 2026 pour un client assujetti ; c'est aussi l'identifiant qui permet le routage.
Nature de l'opération
Livraison de biens, prestation de services ou opération mixte : autre mention devenue obligatoire.
Adresse de livraison
Exigée lorsqu'elle diffère de l'adresse de facturation.
TVA sur les débits
L'option pour le paiement de la TVA d'après les débits doit être mentionnée quand elle est exercée. Elle est reportée dans le XML.
Retard de paiement
Taux des pénalités de retard et indemnité forfaitaire de recouvrement de 40 €, imposés par l'article L441-10 du code de commerce, plus la mention d'escompte.
Exonérations
Chaque taux à 0 % porte son motif : franchise en base, autoliquidation (art. 283-2), livraison intracommunautaire (art. 262 ter I) ou exportation.
Conservation
Factures et pièces se conservent 10 ans (art. L123-22 du code de commerce). Exportez-les dans une sandbox incluse dans vos sauvegardes.

Ce que Lumen ne fait pas encore

Certification PDF/A-3
Le PDF porte bien la pièce jointe, la relation Factur-X et les métadonnées XMP, mais il n'est pas encore certifié PDF/A-3 : il lui manque les polices embarquées et l'intention de sortie ICC. Le XML, lui, est complet — c'est la pièce que traite la plateforme.
Profils BASIC et EXTENDED
Ils ne sont pour l'instant qu'une déclaration : le XML reste celui du profil EN 16931. Un validateur strict signalera l'écart. Laissez EN 16931 tant que rien ne vous impose le contraire.
Transmission
Lumen produit les fichiers ; leur dépôt sur votre plateforme (PDP) ou sur Chorus Pro reste manuel. Le champ « Plateforme » des réglages ne sert aujourd'hui qu'à mémoriser laquelle vous utilisez.
E-reporting
La transmission des données de transaction et de paiement à l'administration n'est pas automatisée.

Projets & tâches

Un projet regroupe des tâches et les documents commerciaux qui les paient : le même écran répond à « où en est le chantier ? » et à « combien en a-t-on déjà facturé ? ».

Trois vues, une seule donnée
Liste (todo, case à cocher, pointage de temps), Kanban (les colonnes sont les statuts de tâche ; le glisser-déposer écrit le statut et l'ordre) et Gantt (barres positionnées sur la fenêtre couverte, trait rouge du jour, retard en rouge). Changer de vue ne change pas la donnée, seulement la façon de la regarder.
Fiche projet
Avancement, tâches en retard, heures passées contre estimées, facturé contre budget, reste dû, devis et factures liés.
Des tâches au devis
« Devis depuis les tâches » transforme les tâches facturables non encore facturées en lignes, en heures au taux horaire du projet. Chaque tâche porte ensuite le numéro du devis : c'est la garde qui empêche de facturer deux fois.
Rattachement
Un devis ou une facture se rattache à un projet dans son éditeur, et la bascule devis → facture transporte ce rattachement.

L'assistant

Le volet Assistant (bord droit, ⌘/Ctrl+J) agit par les outils de l'app, jamais en écrivant directement dans la base.

Tags
L'assistant liste les tags et catégories déjà utilisés avant d'en poser, et sait retrouver « tous les clients tagués grossiste » ou « les articles de la catégorie Matériel ».
Créer
Articles, clients et devis complets à partir d'une demande en français — les prix et les taux sont repris du catalogue quand la référence existe.
Facturer
La bascule d'un devis en facture passe par le même chemin que le bouton : le stock est débité et tracé de la même façon.
Interroger

Contrôler
« Vérifie ma dernière facture » rend la liste des mentions manquantes, bloquantes d'abord.
App · Réunion

Réunion — se voir sans sortir du réseau

Une salle de réunion façon Teams, mais dont le son et l'image ne quittent pas votre réseau : les flux vont de poste à poste (WebRTC), et le poste qui ouvre la salle ne sert qu'à présenter les participants les uns aux autres. Autour de la mosaïque : un fil de discussion, une transcription faite sur chaque machine, et l'assistant, qui sait lire vos documents et vos bases pour répondre en séance.

Ouvrir ou rejoindre

Ouvrir une salle
Votre poste héberge. Lumen ouvre un écouteur sur le port 8767 et vous donne une invitation d'une ligne — 192.168.1.24:8767/ab12/ZK9 — à transmettre par le moyen que vous voulez.
Rejoindre
Collez l'invitation. Le code de salle est exigé avant même l'ouverture de la connexion : un code faux n'ouvre aucun canal.
Portée
Réseau local d'entreprise, ou VPN qui en tient lieu. Il n'y a ni serveur externe, ni STUN, ni TURN : hors de ce réseau, une salle n'est pas joignable. C'est un choix, pas une limite technique oubliée.
Taille
Douze participants au maximum. Au-delà, un maillage complet — chacun émettant vers chacun — se dégrade plus vite qu'il ne rend service.

Pendant la réunion

Micro, caméra, écran
Les bascules sont immédiates : les lignes média sont posées à la connexion et les pistes seulement remplacées, sans renégociation. Le partage d'écran prend la place de la caméra et la rend en s'arrêtant.
Chat
Le fil est commun à la salle et enregistré dans la base « Réunions ».
Transcription
Chaque poste transcrit sa propre voix, localement, avec Whisper — seul le texte circule. Aucun micro n'est envoyé à un service tiers pour être compris. Le premier usage télécharge le modèle choisi dans les réglages.
Enregistrement
Le bouton d'enregistrement capte l'audio de votre poste, lance la transcription, et écrit un fichier .webm dans la sandbox choisie à l'arrêt. Chacun est maître de sa propre trace.

Autorisations

macOS
Au premier usage, le système demande l'accès au micro puis à la caméra. Si vous avez refusé une fois, la demande ne revient pas : allez dans Réglages système → Confidentialité et sécurité → Microphone et Caméra, cochez Lumen, puis relancez l'application. Le partage d'écran dépend en plus de Enregistrement de l'écran.
Sans accès
La salle s'ouvre quand même : vous voyez et entendez les autres, un bandeau explique ce qui manque et un bouton « Réessayer » relance la demande une fois l'autorisation donnée.
Noms des périphériques
Tant que l'accès n'est pas accordé, le système masque le nom des caméras et des micros — la liste des réglages affiche alors « nom masqué » plutôt qu'un modèle. Ce n'est pas un défaut de détection.

Ce qui reste après

Une base SQLite ordinaire, nommée Réunions, avec trois tables : Réunions (titre, date, durée, participants, compte rendu, décisions), Messages de réunion et Transcriptions. Donc relisible par Prisme, interrogeable en français, et exploitable par un agent des mois plus tard.

L'assistant de séance

Examiner des documents
Il liste et lit vraiment les fichiers d'une sandbox — PDF, Word, Excel, PowerPoint, OpenDocument, HTML — avant de répondre. « Que dit l'article 4 du contrat ? » se règle en séance.
Interroger les données
Il enchaîne plusieurs requêtes SQL de lecture sur une base locale puis répond en français, chiffres à l'appui. data_report va plus loin : un rapport écrit, posté dans le fil pour tout le monde.
Programmer la suivante
Titre, date, heure, participants et ordre du jour deviennent un rendez-vous daté, visible dans Tempo · Agenda.
Compte rendu
Objet, participants, points abordés, décisions, actions — rédigé à partir de la transcription et du fil. Sans matière, il le dit au lieu d'inventer. Le texte reste modifiable avant d'être enregistré ou envoyé vers un document Opus.
App · DB Studio

DB Studio — modéliser sa base, pas écrire du SQL

On y décrit des objets métier — un client, un véhicule, une intervention — avec des champs qui ont un sens : « un e-mail », « un montant », « un lien vers un client ». DB Studio en déduit les tables, les contraintes, les relations et le formulaire de saisie. Le moteur, lui, se choisit après : le SQLite local de Lumen, ou un PostgreSQL d'entreprise.

Modèles et champs

Types de champ
Texte court et long, nombre, entier, montant, oui/non, date, date et heure, liste de choix, e-mail, lien web, téléphone, relation. Le type décide du contrôle de saisie et de la validation.
Contraintes
Obligatoire, valeur unique, valeur par défaut, choix autorisés. La même fonction valide le formulaire et les écritures de l'assistant : une contrainte qui ne vaudrait que pour l'interface n'en serait pas une.
Relations
« Un seul » (n–1) ou « plusieurs » (n–n), avec la table cible. À la saisie, la relation devient une liste des enregistrements existants, affichés par leur nom et non par un identifiant.
Ordre
L'ordre des champs est celui du tableau et du formulaire ; les flèches le changent.

Schéma et formulaires

Carte du modèle
Un diagramme des tables et de leurs liens, chaque flèche portant le nom du champ qui la crée.
Formulaire engendré
Titre, introduction, libellé du bouton, champs masqués, aide par champ. Il n'y a pas de formulaire à dessiner : il découle du modèle, et suit ses évolutions.
Données
L'onglet Données affiche les enregistrements, avec les relations résolues en clair, et ouvre le même formulaire pour créer ou corriger.

Espaces — l'écran d'accueil

DB Studio s'ouvre sur une grille de cartes, une par table. Chaque carte porte un chiffre, celui que vous choisissez : le nombre d'entrées, une somme, une moyenne, un minimum ou un maximum sur un champ numérique, ou le nombre d'entrées renseignées. La dernière entrée reçue est rappelée dessous.

Réglage
Le bouton ◔ d'une carte règle sa métrique, son champ et son format (nombre, montant, pourcentage). Le réglage est enregistré avec le modèle, à côté du formulaire.
Calcul
Les agrégations se font en mémoire, sur les 500 premières lignes lues une seule fois par affichage — pas de requête d'agrégation envoyée à la base à chaque repeinte.

Partager une table comme application

Sur une machine à plusieurs profils, une table peut être publiée aux autres sous forme d'application autonome : elle apparaît dans leur menu, ils l'ouvrent, ils saisissent ou consultent. Ils n'entrent jamais dans l'atelier de modélisation.

Trois formes
Saisie et consultation ; saisie seule (un formulaire, sans voir les entrées déjà présentes) ; consultation seule (un tableau, sans formulaire).
Deux droits
Lecture, ou lecture et écriture, profil par profil. Le propriétaire de l'espace est le seul à pouvoir le modifier ou le retirer.
Vérification
Le droit est contrôlé en Rust, à chaque appel : la page partagée ne parle qu'aux commandes dbshare_*, jamais aux commandes de tables. Un espace en lecture n'a aucun chemin d'écriture, et un champ « relation » n'y propose que les lignes d'une table réellement visée par l'espace.
Ce que ce n'est pas
Un cloisonnement du système. Le droit décrit ce que l'ESPACE autorise ; un profil qui ouvre DB Studio lui-même voit les tables comme avant. Le partage sert à donner le bon écran, pas à retirer un accès.
Moteur
Le partage vaut pour le moteur SQLite local de Lumen. Sur un PostgreSQL d'entreprise, les droits se règlent dans le SGBD, là où ils ont un sens pour tous les clients.

Le moteur : SQLite ou PostgreSQL

SQLite local (défaut)
Les modèles deviennent des tables de Lumen : visibles dans Prisme, interrogeables en français, exploitables par Fluxo et les agents, sans passerelle. La nature exacte de chaque champ est conservée dans les métadonnées de la colonne, si bien qu'une table de DB Studio reste une table ordinaire pour le reste de Lumen.
PostgreSQL
Le modèle devient du vrai DDL : clés primaires, clés étrangères, contraintes de liste, tables de jonction pour les relations n–n. Les métadonnées du modèle vivent dans la base elle-même (lumen_dbstudio_meta), donc elles voyagent avec les données.
Sécurité des écritures
Les valeurs passent en paramètres $1…$n — le contenu d'un formulaire ne peut pas être interprété comme du SQL. Les lectures libres sont bornées à un SELECT unique, comme le NL→SQL de SQLite.
Migrations
La création d'un modèle PostgreSQL s'exécute dans une transaction : elle passe entièrement, ou pas du tout.

L'assistant

« Modélise une base de gestion de flotte » suffit à obtenir des tables, des champs typés et des relations cohérentes — puis des enregistrements d'exemple. L'assistant lit toujours le modèle existant avant d'écrire, crée les tables avant les relations qui les visent, et passe par la validation du modèle pour saisir.

App · Reporting

Reporting — des rapports qui se recalculent

Un rapport d'entreprise n'est pas un tableau de bord : il porte sur une période, il compare, il se lit et il s'imprime. Reporting compose des rapports à partir de plusieurs requêtes paramétrées sur vos bases locales, et les rejoue d'un mois sur l'autre sans rien réécrire.

Sources

Requêtes paramétrées
Une source est un SELECT nommé. :debut et :fin y sont remplacés par la période du rapport : changer le mois recalcule tout.
Depuis une question
« Le chiffre d'affaires par mois sur la période » devient une requête SQL, exécutée sous vos yeux avant d'être retenue.
Lecture seule
Toutes les requêtes passent par la garde du moteur de tables : un rapport ne peut rien modifier.

Blocs

Indicateur
Une agrégation (somme, moyenne, compte, min, max) formatée en montant, pourcentage ou entier — et comparée à la période précédente, la même requête rejouée sur la fenêtre d'avant. Un chiffre sans variation ne dit rien.
Graphiques
Barres, barres horizontales, courbe, aire, secteurs, anneau, nuage de points, jauge. Les couleurs suivent l'accent de l'orbe et le thème clair/sombre.
Tableaux
Colonnes choisies, nombre de lignes borné.
Titres et texte
Un rapport se rédige aussi : sections et paragraphes font partie du document.
Analyse rédigée
Un bloc où l'IA interroge réellement la base — plusieurs requêtes — puis commente les chiffres. Le texte reste modifiable avant publication.
Mise en page
Chaque bloc occupe un tiers, une moitié, deux tiers ou toute la largeur.

Diffuser

Enregistrement
Un rapport est un fichier JSON dans une sandbox : il se copie, se sauvegarde et se relit sans base cachée.
Export HTML
Un fichier autonome, styles inclus et graphiques transformés en images, qui s'ouvre partout — sans Lumen.
Impression / PDF
La feuille d'impression retire la coquille de l'application et évite de couper un bloc en deux.
App · Sources de données

Sources de données — brancher le dehors, en lecture seule

Les applications Pro travaillent sur des données qui vivent ailleurs : le PostgreSQL métier, le partage SharePoint, le bucket MinIO, un export Excel, un dépôt GitHub. Le centre de connexions les déclare une fois, puis les met à disposition par une seule porte — une API REST locale, doublée d'un point d'entrée MCP. Cette porte ne sait que lire.

Connecteurs

Bases de données
PostgreSQL / PostGIS, MySQL / MariaDB, SQL Server, SQLite. SQLite est ouvert avec le drapeau READ_ONLY du pilote ; PostgreSQL voit sa session passée en default_transaction_read_only.
Fichiers
Classeurs Excel / OpenDocument — une feuille devient un jeu de données, noté classeur.xlsx#Feuille — et CSV, fichier par fichier ou dossier entier. La source a une racine, et ne voit rien au-dessus.
Stockage
WebDAV, Nextcloud (mot de passe d'application), S3 / MinIO (signature SigV4, calculée sur place et uniquement pour des GET).
Services
SharePoint et OneDrive via Microsoft Graph, Google Drive (les documents natifs sont exportés en texte), GitHub, et toute API REST dont vous déclarez les points d'entrée.

Lecture seule, par construction

La garantie ne repose pas sur un filtre que l'on pourrait contourner, mais sur du code qui n'existe pas.

Un vocabulaire fini
Lister les sources, lister les jeux de données, décrire un schéma, lire des lignes, lister des objets, lire un objet. Six verbes, pas un de plus — un modèle ne peut pas en inventer un septième.
Aucune route d'écriture
Seuls des GET sont routés. Toute autre méthode répond 405. Le seul POST de données est /query, parce qu'un SQL ne tient pas dans une URL.
Le SQL libre est fermé par défaut
Il faut le cocher source par source. Même autorisé, la requête doit passer la même garde que le NL→SQL de Lumen : un seul ordre, commençant par SELECT ou WITH, sans mot-clé d'écriture — un WITH … AS (INSERT …) est refusé.
Rien vers l'extérieur
Les connecteurs distants n'émettent que GET et PROPFIND (la lecture d'un dossier WebDAV). Aucun PUT, DELETE ou MKCOL n'est construit nulle part.
Dormante par défaut
Une source ajoutée n'est pas exposée : tant que la case n'est pas cochée, elle n'existe ni pour l'API, ni pour les modèles. C'est le même principe que les serveurs MCP inactifs.

L'API

Adresse
http://127.0.0.1:8771 — l'écoute est limitée à la boucle locale : rien n'est joignable depuis le réseau.
Jeton
Toutes les routes exigent Authorization: Bearer …. Le jeton est tiré au sort à la première activation et lisible dans l'onglet « API & MCP ».
Routes
/v1/sources, /v1/sources/{id}/datasets, …/datasets/{nom}/schema, …/datasets/{nom}/rows (limit, offset, select, order_by, et tout autre paramètre devient un filtre d'égalité), …/objects?path=, …/object?path=.
Description
/v1/openapi.json décrit la surface, et dit explicitement qu'elle est en lecture seule : c'est la première chose que lit un agent qui la découvre.
MCP
POST /mcp expose les mêmes fonctions en JSON-RPC. Les sept outils portent tous l'annotation readOnlyHint — un modèle branché en MCP n'a pas plus de pouvoir qu'un client HTTP.

Secrets

Mots de passe, jetons et clés sont enregistrés à part, dans un fichier en 0600 à côté de mcp.json. Ils ne redescendent jamais dans l'interface : les champs reviennent vides, et un champ laissé vide conserve la valeur enregistrée. Ni l'API ni les outils MCP ne les publient — /v1/sources ne donne que le nom des secrets renseignés.

Apps · Annuaire & Messagerie

Le réseau — quand Lumen cesse d'être seul

Ces deux applications ne servent à rien sans un Lumen Server : un serveur d'équipe auto-hébergé, produit distinct, qui porte les identités, transporte les messages et fait tourner l'inférence partagée. Tant qu'aucun serveur n'est lié, elles le disent et le reste de Lumen ne change pas d'un pouce.

Lier ce poste

Un code, une fois
L'administrateur crée votre compte et vous remet un code d'appairage valable dix minutes. Vous le saisissez dans l'Annuaire ; le poste reçoit un jeton d'appareil que l'interface ne voit jamais — il vit côté Rust, dans un fichier 0600.
Une paire de clés
Produite sur le poste au moment de la liaison. Seule la publique part vers le serveur ; la privée ne quitte jamais la machine et n'est envoyée par aucune commande.
Blocage
Un administrateur peut bloquer un compte : tous ses appareils sont refusés à la requête suivante, sans qu'il faille les révoquer un à un.

Messagerie chiffrée de bout en bout

Le serveur ne range que du chiffré : une enveloppe par appareil destinataire, closes sur le poste émetteur. Il connaît qui écrit à qui, quand, et quelle taille — jamais le contenu.

Trois conséquences
La recherche est locale (le serveur n'indexe rien). Un appareil appairé après coup ne voit pas le passé — il n'était destinataire d'aucune enveloppe. Perdre tous ses appareils, c'est perdre son historique : aucun administrateur ne peut le restituer.
Ce qui s'affiche
Un message qu'on ne peut pas ouvrir est montré comme tel, plutôt que de disparaître en silence.
Primitive
ECDH P-256 + HKDF-SHA256 + AES-GCM, via WebCrypto. Pas X25519 : il n'est pas disponible sur toutes les webviews que Lumen vise.

Ce que le serveur apporte au reste de Lumen

Réunions
Les salles sont signalées par le serveur : plus besoin qu'un poste reste allumé pour héberger. L'audio et la vidéo restent pair-à-pair.
Inférence
Le serveur expose une API compatible OpenAI et répartit les requêtes entre lui-même et des nodes — des machines qui ne font que servir du llama.cpp. Un poste sans GPU génère à la vitesse de l'atelier.
DB Studio
Un troisième moteur, « Lumen Server (partagé) » : les tables vivent sur le serveur, avec des droits par compte réseau — lecture ou écriture, vérifiés à chaque appel. Seul le propriétaire décide des accès.
Agents
Un agent publié au serveur s'exécute sans que votre portable reste ouvert. Les effets sensibles suspendent l'exécution et demandent votre accord sur la socket ; personne ne l'approuve à votre place.

Ce qui n'est pas garanti

Les messages sont chiffrés de bout en bout ; les tables et les fichiers ne le sont pas — l'administrateur du serveur peut les lire, et un serveur compromis les expose. Le serveur voit aussi les métadonnées des conversations : qui écrit à qui, quand, combien. Lumen Server déplace la confiance vers une machine ; il la réduit sur les messages, il ne la supprime nulle part.

App · Flux de données

Flux de données — transformer sous ses yeux

Un ETL : lire des données là où elles sont, les transformer étape par étape, écrire le résultat ailleurs. Ce qui le distingue, c'est qu'on voit le résultat pendant qu'on le construit — pas à la fin.

Trois principes

On voit ce qu'on fait
Chaque étape ajoutée rejoue le flux sur un échantillon de 200 lignes et l'aperçu se met à jour. Un ETL qui ne montre son résultat qu'à l'exécution se débogue à l'aveugle.
La trace dit où sont passées les lignes
Après chaque étape : combien de lignes, combien de colonnes, et l'erreur s'il y en a une. C'est la première question qu'on se pose devant un résultat vide.
La source n'est jamais modifiée
Un flux LIT une source et ÉCRIT une destination, toujours distinctes. Un ETL qui écrase ses entrées n'est pas rejouable — et rejouer est tout l'intérêt d'un flux enregistré.

Sources et destinations

Sources
Les tables de Lumen (Prisme), tout le centre de sources de données — donc PostgreSQL, MySQL, SQL Server, Excel, REST, S3… — et les fichiers CSV d'une sandbox.
Destinations
Un CSV dans une sandbox, ou une table de Lumen — aussitôt lisible par Prisme, Calc, Reporting et les agents.
Enregistrement
Un flux est un fichier JSON dans une sandbox : il se copie, se sauvegarde et se relit sans base cachée.

Les étapes

Colonnes
Garder, retirer, renommer.
Lignes
Filtrer (dix opérateurs), trier, dédoublonner, limiter.
Calcul
Colonne calculée, avec des expressions du type [prix] * [quantité]. Les décimales à la virgule sont acceptées : un CSV français en est plein.
Agrégation
Regrouper par une ou plusieurs colonnes, avec nombre, somme, moyenne, minimum, maximum, première valeur ou liste.
Jointure
Rapprocher un second jeu sur une clé. Par défaut à gauche : les lignes sans correspondance sont conservées avec des cases vides, plutôt que de disparaître en silence.

Les expressions n'exécutent pas de code

Une expression de colonne calculée n'est pas évaluée en JavaScript. Un interpréteur minuscule comprend les colonnes entre crochets, les nombres, les textes, les quatre opérations et les parenthèses — et refuse tout le reste, y compris un simple identifiant. Un flux partagé, ou écrit par un modèle, ne peut donc rien exécuter dans la page.

L'assistant

Il construit le flux avec vous : il lit d'abord les colonnes réelles, ajoute une étape, vérifie le nombre de lignes restantes, et le dit quand un filtre vide le jeu. Il n'exécute le flux que si vous le demandez — c'est l'exécution qui écrit dans la destination.

Pourquoi pas Fluxo

Fluxo orchestre des actions dans le temps : lancer, attendre, notifier, brancher. Un ETL transforme une table : filtrer, dériver, regrouper, joindre. Plier ces opérations en blocs Fluxo aurait donné des workflows illisibles pour dire « garde les lignes où le montant dépasse 1000 ». Les deux se rejoignent ailleurs : un flux enregistré est un fichier, et Fluxo saura le déclencher.

Sur macOS et Linux, la touche indiquée ⌘ correspond à Ctrl sous Linux et Windows. Le panneau d'aide de Lumen affiche automatiquement la bonne.

Pourquoi pas ⌘Tab ou Alt+Tab ?

Lumen Desktop est un bureau qui s'exécute à l'intérieur d'une fenêtre. Les raccourcis que le système d'exploitation s'est réservés ne parviennent jamais à l'application : ⌘Tab est capté par macOS, Alt+Tab par le gestionnaire de fenêtres sous Linux et Windows. Ils continuent donc de basculer entre les applications de l'ordinateur, et aucun réglage de Lumen ne peut le changer.

Le sélecteur de fenêtres de Lumen répond en conséquence à Ctrl+Tab sur toutes les plateformes, et à ⌥Tab en plus sur macOS, où cette combinaison reste libre. Le geste est identique à celui du système : maintenir, tabuler, relâcher.

App · Calc

Calc — le tableur

Le troisième volet de l’atelier bureautique, à côté d’Opus : une grille, des formules, des graphiques. Sa particularité tient à ce qu’il y a autour — une feuille peut venir d’une table SQLite locale ou d’une question posée en français, et repartir vers l’Analyse de données ou vers une nouvelle table, sans fichier intermédiaire.

Le langage des formules

La syntaxe est celle de LibreOffice Calc et d’Excel : une formule commence par un signe égal, les arguments se séparent par un point-virgule, et les noms de fonctions existent en français comme en anglais. Une feuille écrite ailleurs reste donc calculable ici, et inversement. Ce n’est pas un langage de programmation : il n’y a ni variable, ni boucle, ni macro — une cellule contient une expression, réévaluée à chaque modification.

=A1+B2*3
=SOMME(A1:A20)            =SUM(A1:A20)
=SI(B2>10;"atteint";"en cours")
=MOYENNE(C2:C9)/1000
=A1&" — "&B1
=RECHERCHEV(D2;A1:C50;3)
=ARRONDI(SOMME(A1:A9)*20%;2)
=SIERREUR(B1/C1;"n/a")
Opérateurs
Arithmétique + − * / ^ (puissance) et % en suffixe (50% vaut 0,5). Comparaisons = <> < <= > >= qui renvoient VRAI ou FAUX. Concaténation de texte avec &. Les parenthèses forcent l’ordre habituel. Comme dans Calc, le moins unaire est prioritaire sur la puissance : -A1^2 avec A1 = 10 donne 100.
Références
A1 pour une cellule, A1:C20 pour une plage. Le dollar fige une référence ($A$1, A$1) : à la copie ou au collage, les références relatives sont décalées, les absolues non. Les références vers une AUTRE feuille ne sont pas encore reconnues.
Séparateur d’arguments
Le point-virgule est la forme attendue, mais la virgule est acceptée : les deux conventions circulent selon le tableur d’origine, et refuser l’une des deux ne produirait que des erreurs incompréhensibles.
Texte, nombres, booléens
Une saisie qui ressemble à un nombre en devient un (la virgule décimale est comprise). Une apostrophe de tête force le texte : 'BONJOUR, ou '=ceci-n-est-pas-une-formule. VRAI et FAUX (TRUE et FALSE) sont reconnus.
Erreurs
Une cellule fautive affiche son erreur et la propage à celles qui en dépendent, sans jamais interrompre le calcul du reste : #DIV/0!, #VALEUR!, #NOM?, #REF!, #N/A, #NOMBRE!, #SYNTAXE!, et #CIRC! pour une référence circulaire, détectée au lieu de bloquer.

Fonctions disponibles

Quarante et une fonctions, chacune atteignable par son nom français ou anglais — soixante-dix-sept noms reconnus au total. Un nom inconnu renvoie #NOM? plutôt que d’échouer en silence.

Calcul
SOMME SUM · MOYENNE AVERAGE · MIN · MAX · ARRONDI ROUND · ABS · RACINE SQRT · PUISSANCE POWER · MOD · ENT INT · ALEA RAND · PI
Statistiques
NB COUNT · NBVAL COUNTA · MEDIANE MEDIAN · ECARTYPE STDEV · ECARTYPEP STDEVP
Logique
SI IF · SIERREUR IFERROR · ET AND · OU OR · NON NOT
Texte
CONCATENER CONCAT · NBCAR LEN · MAJUSCULE UPPER · MINUSCULE LOWER · SUPPRESPACE TRIM · GAUCHE LEFT · DROITE RIGHT · STXT MID
Dates
AUJOURDHUI TODAY · MAINTENANT NOW · ANNEE YEAR · MOIS MONTH · JOUR DAY
Conditionnelles et recherche
SOMME.SI SUMIF · NB.SI COUNTIF · MOYENNE.SI AVERAGEIF · RECHERCHEV VLOOKUP · INDEX · EQUIV MATCH

Les critères des fonctions conditionnelles suivent la convention de Calc : une valeur (42), un texte entre guillemets, ou une comparaison écrite entre guillemets — « >10 », « <>annulé ».

La grille

Saisie
Taper remplace, Entrée valide et descend, Tabulation valide et va à droite, F2 ou double-clic modifie sans effacer, Échap annule. La barre de formule affiche toujours la saisie brute de la cellule active, formule comprise.
Sélection
Clic, glisser ou Maj + flèches pour une plage ; clic sur un en-tête de colonne ou de ligne pour la sélectionner entière. La barre du bas donne en continu la somme, la moyenne et le nombre de cellules remplies.
Presse-papiers
⌘C, ⌘X et ⌘V. En interne, formules et mise en forme sont conservées et les références relatives décalées. Vers l’extérieur, la sélection part en texte tabulé, directement collable dans LibreOffice, Excel ou Google Sheets — et l’inverse fonctionne aussi.
Mise en forme
Gras, italique, souligné, couleur du texte et du fond, alignement. Formats de nombre : automatique, monnaie, pourcentage, date, avec ajout et retrait de décimales.
Structure
Insertion et suppression de lignes et de colonnes, largeur de colonne ajustable à la souris, tri croissant ou décroissant sur la colonne active avec détection de la ligne d’en-tête, somme automatique, feuilles multiples (double-clic pour renommer, clic droit pour supprimer), annulation illimitée dans la session.

Une réserve à connaître : insérer ou supprimer une ligne déplace les cellules et leur mise en forme, mais ne réécrit pas les formules qui les visaient. C’est délibéré — un décalage silencieux de références fait plus de dégâts qu’un #REF! visible.

Le volet de droite

Données
Importer une table locale dans une nouvelle feuille, qui garde son lien d’origine et se réactualise d’un bouton. Poser une question en français : elle est traduite en SQL de lecture seule et le résultat arrive dans une feuille. Renvoyer la feuille courante vers une nouvelle table. Écrire un CSV dans la sandbox et ouvrir l’onglet Analyse dans la foulée.
Graphique
Crée une feuille graphique : un onglet à part entière du classeur, recalculé à partir d’une feuille de données (toute la feuille, ou la plage sélectionnée). On y choisit le type (barres, barres horizontales, courbes, aires, secteurs, anneau, nuage de points), le champ de catégorie, et une ou plusieurs séries — chacune avec son champ et son agrégation (somme, moyenne, nombre, médiane, min, max…) quand les lignes sont regroupées par catégorie. Des champs calculés se déclarent par formule ([Prix] * [Quantité], if([Total] > 100, "gros", "petit")) et s’utilisent ensuite comme les autres. Tri, top N, empilement, valeurs affichées ; export en PNG dans la sandbox. Tout est enregistré dans le .lumensheet.
IA
Décrire un calcul en français : la formule correspondante est écrite dans la cellule active. Ou faire analyser la sélection, avec une réponse en quelques phrases.

Fichiers

Format natif
Les classeurs s’enregistrent en .lumensheet dans la sandbox — du JSON lisible qui contient les feuilles, les saisies brutes et la mise en forme. Ils apparaissent en vert dans l’explorateur et s’ouvrent d’un double-clic.
CSV
Import depuis la sandbox dans une nouvelle feuille, export de la feuille courante. À l’import, une valeur commençant par un signe égal est neutralisée : un fichier reçu ne doit pas exécuter de formule.
Ouvrir depuis ailleurs
Un .lumensheet, un .csv ou un .tsv s’ouvre dans Calc depuis le menu contextuel de l’explorateur et depuis la recherche ⌘K. Dans l’autre sens, l’Analyse de données propose « Ouvrir dans Calc » pour le jeu de données chargé.

Matériel · Panneau physique

Lumen Controller

Un boîtier à molette, boutons, potentiomètre, écran e-paper, bandeau LED et lecteur RFID qui pilote Lumen sans passer par le clavier. Le firmware MicroPython vit dans le dossier lumen-controller/ et tourne sur ESP32 ou Raspberry Pi Pico W.

Ce qu'il fait

Molette
Change le modèle, la voix de synthèse ou la couleur de repos des LEDs. Son poussoir choisit laquelle de ces trois fonctions est active ; un appui long arrête tout (lecture vocale, génération, workflow).
Bouton Backend
Appui court : backend suivant (Ollama → llama.cpp → Apple → API). Appui long : charge en mémoire le modèle affiché.
Bouton Micro
Appui court : dictée, puis envoi du message. Appui long : nouvelle conversation.
Bouton Mode
Mode de discussion : Chat → Router → Tools → Docs.
Potentiomètre
Volume de sortie de l'ordinateur, appliqué par Lumen (commande réseau hid_volume, pas de HID USB).
Lecteur RFID
Envoie l'UID du badge posé ; c'est Lumen qui décide de l'action associée. Le badge retiré est signalé, ce qui permet de le reposer pour rejouer l'action.
Écran e-paper
Backend, modèle, volume, état de Lumen, voix active, mode de discussion, débit en tokens/s et occupation du contexte (CTX 2.5k/8k). Tant que Lumen n'est pas relié, il affiche l'adresse IP à saisir dans les Réglages.

Le bandeau LED

L'écran e-paper met plusieurs centaines de millisecondes à se redessiner : les LEDs WS2812B donnent l'information instantanée, visible de loin.

Repos
Couleur choisie à la molette, respiration lente.
Écoute
Bleu, pulsation.
Réflexion
Ambre, pulsation.
Réponse
Vert d'eau, pulsation.
Chargement
Violet, pulsation.
Erreur
Rouge, fixe.
ⓘ

Les couleurs d'état ne sont pas configurables : ce sont des significations, pas une décoration. Seules la couleur de repos (molette) et la couleur des notifications (Réglages) se choisissent.

Notifications lumineuses

À chaque notification du centre de notifications, le bandeau joue un pulse rapide pendant environ quatre secondes, puis rend la main à la couleur d'état. La couleur se choisit dans Paramètres → Notifications → Notifications lumineuses ; le bouton Tester l'envoie immédiatement à la carte.

  1. Reliez le contrôleur (Réglages → adresse du Lumen Controller).
  2. Choisissez la couleur. Elle est mémorisée et jointe à chaque notification envoyée.
  3. Le firmware la reçoit dans le champ notification.color ; s'il n'en reçoit aucune, il utilise NOTIFY_COLOR de son config.py.
💡

La durée du pulse se règle sur la carte avec NOTIFY_MS (4000 ms par défaut). Le pulse descend presque à l'extinction, là où les états respirent entre 25 % et 100 % : c'est ce qui le rend reconnaissable au premier coup d'œil.

Installation

  1. Flashez MicroPython sur la carte (ESP32 ou Pico W), puis copiez tous les *.py du dossier lumen-controller/.
  2. Créez un config_local.py avec votre SSID, votre mot de passe et les GPIO de votre carte : il surcharge config.py sans le modifier.
  3. Redémarrez. L'écran affiche l'adresse IP obtenue (elle est aussi imprimée sur la console série).
  4. Dans Lumen, saisissez cette adresse comme Lumen Controller. Le port par défaut est 8787.

Le câblage détaillé, les profils ESP32/Pico W et le dépannage de l'écran sont dans lumen-controller/WAVESHARE-2IN13.md.

Protocole

Le contrôleur est le serveur TCP (port 8787) et Lumen le client : c'est ce qui permet à l'application de se reconnecter seule après un redémarrage de la carte. Le transport est du JSON, une ligne par message, dans les deux sens, sans accusé de réception.

Contrôleur → Lumen
{"type":"command","cmd":"dictation"}, set_model, set_backend, set_mode, set_voice, load_model, hid_volume, new_chat, stop, rfid, rfid_removed.
Lumen → contrôleur
État (backend, model, status, chat_mode, voice, ctx_used/ctx_total, tps), catalogue des modèles et des voix, et notification (texte, source, couleur).
hello
À la connexion, le contrôleur annonce protocol: 2 et ses capacités (chat_mode, voice, leds, notify_leds, rfid_presence). Lumen s'en sert notamment pour ne pas lui envoyer d'audio brut, qu'il ne sait pas lire.
ⓘ

C'est le message hello — et non le champ de configuration utilisé — qui identifie le contrôleur : Lumen sait donc à quoi il parle avant de lui envoyer quoi que ce soit.

Lumen sort de l'écran : un panneau de contrôle physique, des capteurs et des actionneurs. Ces cartes tournent en MicroPython, sur votre réseau local, sans cloud ni broker.

État brut, catalogue des modèles et des voix, débit en tokens/s, occupation du contexte, notifications (avec leur couleur).

Aller plus loin · API

API développeur

Lumen expose un petit serveur HTTP sur la boucle locale http://127.0.0.1:8765 (accessible à vos raccourcis et scripts, jamais au réseau). Vos raccourcis lui renvoient des informations par de simples requêtes.

1 · Progression d'un run

Pendant un run en mode Action, POSTez chaque étape. run_id vous est fourni dans l'enveloppe d'entrée du raccourci. kind : progress, step, result, success, error.

POST http://127.0.0.1:8765/run/progress
Content-Type: application/json

{ "run_id": "…", "kind": "progress", "message": "Téléchargement…" }

La couleur de la puce dépend du kind : progress/step/status (étape en cours), tool (outil appelé), inference/model/ai (appel modèle), success/result (réussite), error (échec), image (image envoyée).

2 · Afficher un widget

Choisissez un template et fournissez ses champs. Gabarits : weather, metric, stat-grid, list, gauge, report, sport. accent (hex) et icon sont optionnels.

POST http://127.0.0.1:8765/run/widget

{ "run_id": "…", "template": "weather", "title": "Paris",
  "temp": 18, "unit": "C", "condition": "Nuageux",
  "location": "Paris", "hi": 21, "lo": 12,
  "hourly": [{"time":"14h","temp":18},{"time":"15h","temp":19}] }
{ "template": "metric", "title": "AAPL", "value": "227,5",
  "unit": "$", "trend": "up", "delta": "+1,2 %" }

{ "template": "stat-grid", "title": "Système",
  "items": [ {"label":"CPU","value":"34 %"}, {"label":"RAM","value":"11 Go"} ] }

{ "template": "gauge", "title": "Batterie", "value": 72, "label": "72 % — 4 h" }

{ "template": "report", "title": "Sauvegarde", "status": "success",
  "lines": [ {"label":"Fichiers","value":"1 240","state":"ok"} ] }

3 · Afficher une image

Encodez l'image en Base64 et POSTez-la ; elle s'affiche dans la bulle, côté bureau et mobile.

POST http://127.0.0.1:8765/run/image
{ "run_id": "…", "image_b64": "iVBORw0KGgo…", "mime": "image/png" }

4 · Notification flottante

Affiche une capsule de verre flottante, indépendante de la fenêtre, qui hérite du thème clair/sombre. Autonome : pas besoin de run_id. kind : info, success, warn, error, prompt, progress, thinking. timeout_ms à 0 = reste affiché. Avec des actions, la capsule reste jusqu'au clic.

POST http://127.0.0.1:8765/notify

{ "kind": "success", "icon": "sparkles", "title": "Terminé ✨",
  "body": "412 fichiers copiés.", "timeout_ms": 6000,
  "actions": [ {"id":"open","label":"Ouvrir","primary":true},
               {"id":"later","label":"Plus tard"} ] }

5 · Mémoire partagée (clé/valeur)

Un magasin clé/valeur persistant, namespacé (todo/, state/, user/, store/). C'est la mémoire opérationnelle des raccourcis et du heartbeat — parfaite pour l'état d'une boucle d'agent.

GET    /mem/<clé>            → lire
PUT    /mem/<clé>            → écrire (corps = valeur JSON)
POST   /mem/<clé>?op=append  → ajouter à un tableau
DELETE /mem/<clé>            → supprimer
GET    /mem?ns=todo/         → lister

6 · Bases de données locales dans vos mini-apps

Les apps HTML lancées depuis la sandbox reçoivent un pont JavaScript window.lumen.tables. Les méthodes de lecture sont toujours disponibles ; les méthodes d'écriture nécessitent d'activer Écriture BDD dans la barre du runner, et l'autorisation retombe à off à chaque lancement.

// Lire les bases et tables
const bases = await window.lumen.tables.listBases();
const baseId = bases[0].base_id;
const tables = await window.lumen.tables.listTables(baseId);

// Lire un schéma, des lignes, ou exécuter un SELECT
const schema = await window.lumen.tables.baseSchema(baseId);
const rows = await window.lumen.tables.rows(tables[0].table_id, 50, 0);
const result = await window.lumen.tables.query(baseId, 'SELECT * FROM "Clients" LIMIT 10');

// Export CSV d'une table
const csv = await window.lumen.tables.exportCsv(tables[0].table_id);

Méthodes d'écriture disponibles uniquement après autorisation : createBase, createTable, addColumn, insertRow, updateRow, deleteRow.

7 · Rechercher dans vos documents (RAG)

La même recherche hybride que l'app Connaissances, exposée en HTTP : mots-clés et similarité vectorielle fusionnés, un score par extrait. Utile à un raccourci, à un script, ou à une mini-app qui veut citer vos documents.

POST http://127.0.0.1:8765/rag/search
Content-Type: application/json

{ "query": "entretien courant", "k": 5 }

La réponse est un tableau d'extraits. Chacun porte son texte, le titre et l'identifiant du document, son rang dans celui-ci, un score de pertinence entre 0 et 1, et un indicateur disant s'il a été trouvé par mot-clé.

ⓘ

Le score dépend de l'encodeur d'embeddings : comparez les extraits d'une même réponse entre eux, jamais à un seuil écrit en dur.

Au-dessus du magasin clé/valeur, Lumen modélise 8 types de souvenirs inspirés des architectures cognitives. Ils se gèrent dans l'app dédiée Mémoire (Boîte à outils), et l'IA y accède selon une politique d'accès cloisonnée.

Épisodique
Événements vécus, horodatés : ce qui s'est passé.
Sémantique
Faits stables sur vous et le monde.
Procédurale
Savoir-faire, recettes, façons de faire.
Émotionnelle
Préférences affectives, ton, ce qui plaît ou agace.
Prospective
Intentions et rappels tournés vers le futur.
Comportementale
Habitudes et régularités observées.
Narrative
Le récit évolutif de la relation, l'identité de Lumen.

Rappel intelligent

Le rappel ne fait pas qu'une recherche par mot-clé : il mélange pertinence lexicale, récence (chaque type a sa demi-vie : un épisode vieillit vite, un fait sémantique très lentement) et saillance (importance, renforcée à chaque rappel). Les souvenirs épinglés ne sont jamais élagués. Tout est local et hors-ligne ; aucun appel réseau n'est requis.

Accès cloisonné (sécurité)

Chaque appelant (la barre, un agent, domotique, studio…) porte un contexte. Une politique décide, par (contexte, type), un accès aucun / lecture / écriture. L'application de la règle se fait côté backend : un agent ou un bloc Fluxo compromis (injection de prompt) ne peut pas lire un type qu'on ne lui a pas ouvert. Par défaut, la barre lit le sémantique/émotionnel/narratif et écrit l'épisodique/prospectif ; la domotique ne voit que le comportemental ; etc. Vous ajustez tout dans l'onglet Accès & sécurité de l'app Mémoire.

L'IA de la barre dispose de deux outils : memory_recall (se souvenir avant de répondre) et memory_remember (retenir un fait durable) — toujours bornés par la politique. Les types émotionnel et narratif, plus intimes, sont stockés avec des permissions fichier restreintes (0600). Chaque type peut être purgé d'un geste (« Tout effacer »).

9 · Sécurité des accès & des secrets

/run/*, /notify et /mem/* n'écoutent que sur 127.0.0.1 : réservés à votre Mac, sans authentification. Le compagnon mobile (port 8766) est, lui, protégé par TOTP. La passerelle Telegram n'ouvre aucun port : elle interroge Telegram en sortie et n'écoute que les conversations appairées.

Clé API cloud. La clé n'est jamais conservée côté interface (plus de localStorage). Elle vit uniquement dans un fichier protégé côté application (0600) et n'est utilisée que par un proxy backend : toutes les requêtes vers l'API passent par lui, qui injecte la clé et la verrouille sur l'endpoint configuré. Conséquence : même une page compromise ne peut ni lire la clé, ni l'exfiltrer vers un autre serveur. Dans Paramètres → IA, un champ vide signifie « conserver la clé déjà enregistrée » ; le bouton Retirer la clé l'efface.

Le protocole « Lumen Local Device »

Pensé comme un équivalent d'ESP-NOW mais adapté au Wi-Fi/IP :

  1. Découverte : Lumen diffuse une sonde UDP en broadcast (port 50001) ; chaque carte répond par une annonce JSON (id, nom, type, IP, port).
  2. Contrôle : Lumen envoie des requêtes HTTP signées HMAC-SHA256 avec une clé partagée. La signature empêche le rejeu et garantit que seul Lumen pilote l'objet — la clé ne circule jamais sur le réseau.
ⓘ

Chaque objet a sa clé partagée, générée à la création du firmware et conservée par Lumen. Après une découverte, renseignez cette clé (⚙︎ sur la carte) pour pouvoir piloter l'objet.

Flasher une carte

  1. Installez MicroPython sur la carte (esptool pour ESP32 / ESP32-S3, glisser le .uf2 pour le Pico W).
  2. Copiez le main.py généré à la racine de la carte (Thonny ou mpremote fs cp main.py :).
  3. Redémarrez : la carte rejoint le Wi-Fi puis répond à la découverte de Lumen.
💡

Pas de matériel sous la main ? Lancez le simulateur node scripts/mock-domotique.mjs : il crée 4 objets virtuels sur 127.0.0.1 (clé lumentest) qui répondent au protocole, pour tester l'app de bout en bout.

Robot Studio

Programmer un Raspberry Pi par blocs : le Python est généré, puis déployé et lancé sur le Pi en SSH.

Assembler un programme

Glissez des blocs depuis la boîte à blocs : démarrage (exécuté une fois) et boucle (exécutée en continu) structurent le programme. Les catégories couvrent les broches GPIO, LED et rubans WS2812B, servomoteurs, capteurs (DHT, DS18B20, ultrasons, PIR, encodeurs, ADS1015, RFID, infrarouge), caméra, réseau (HTTP, MQTT, WebSocket), mémoire locale, IA (Ollama, YOLO sur Hailo, modèles locaux), écran et audio.

L'onglet Python montre le code généré et la liste des paquets pip nécessaires. L'onglet Aide des blocs explique le bloc sélectionné.

Déployer sur le Pi

  1. Autorisez votre clé SSH une fois depuis le Terminal : ssh-copy-id pi@raspberrypi.local. Lumen n'utilise jamais de mot de passe.
  2. Dans l'onglet Appareils, ajoutez le Pi (adresse, utilisateur, port) puis Tester la connexion.
  3. Préparer le Pi crée l'environnement Python ~/rpirobotstudio (une seule fois).

État, Journal et Arrêter pilotent le programme à distance. Exporter enregistre les mêmes fichiers dans une sandbox, sans rien envoyer.

Principe

Recherche profonde

Le déroulé d'une enquête

  1. L'IA décompose la question en angles de recherche complémentaires. La question telle que vous l'avez écrite reste le premier angle : les reformulations perdent souvent les mots exacts du document, sur lesquels la recherche par mot-clé est la plus sûre.

Barre & bureau

Documents en discussion

Poser une question sur un document sans quitter la conversation. Deux chemins : joindre un fichier au fil, ou passer la discussion en mode Documents pour interroger toute votre base.

Joindre un document

Le trombone de la barre accepte PDF, DOCX, texte, Markdown, CSV, JSON — le glisser-déposer aussi. Ce qui se passe ensuite dépend de la taille :

Document court
En dessous d'environ 24 000 caractères, le texte part en entier dans le contexte du modèle, une seule fois. C'est le régime le plus fidèle : rien n'est sélectionné, donc rien ne manque. Idéal pour un résumé.
Document long
Au-delà, le document est indexé et consulté par extraits à chaque question. La pastille du fichier indique le régime retenu.
Éphémère
Un document joint à une discussion est retiré de l'index quand vous le détachez ou repartez de zéro. Il n'encombre pas votre bibliothèque.

Les modes de discussion

Le sélecteur de la barre décide de ce qui arrive à votre question. Un seul mode est actif à la fois, et il est partagé avec la discussion du bureau.

Discussion
Le modèle répond directement. C'est le mode par défaut.
Documents
La question interroge d'abord votre base documentaire, et la réponse s'appuie sur les extraits trouvés.
Routeur
La demande part au workflow Fluxo « default router », qui décide de l'action à mener et rend compte de sa progression en direct.
Outils
Function calling : le modèle appelle lui-même les workflows Fluxo publiés comme outils.
Documentation
Function calling restreint à la documentation de Lumen : pour les questions sur l'app elle-même.
Un workflow précis
Sous le séparateur, chaque workflow Fluxo peut recevoir directement la demande.

Ce que fait le mode Documents

Toute la base
Chaque question interroge la bibliothèque entière, pièces jointes comprises, et les passages trouvés accompagnent la question.
Sans outil
La recherche a lieu avant la génération, le modèle n'a donc pas à savoir appeler un outil — ce dont les petits modèles locaux s'acquittent mal. Le bouton Mémoire est estompé dans ce mode : il n'y a pas de boucle d'outils pour l'exécuter.
Base vide
Si rien n'est indexé, Lumen le dit au lieu de laisser le modèle répondre de mémoire en donnant l'illusion d'avoir lu vos documents.
ⓘ

Le mode est partagé avec la discussion du bureau : le choisir dans la barre le règle des deux côtés.

Le panneau Sources

Sous une réponse tirée de documents, une pastille par passage retenu : son numéro, son origine et son score de pertinence. Un clic ouvre l'extrait complet, un second le referme.

Numéros

À la voix

Podcast IA

Transformez vos documents en une discussion audio à deux voix, façon « notebook » audio — entièrement en local.

Comment ça marche

  1. Donnez une source : un document de la sandbox, des notes, un texte collé. L'option Connaissances ajoute au script les extraits pertinents de votre base documentaire.
  2. L'IA en tire un script de dialogue entre deux interlocuteurs qui se répondent et vulgarisent le contenu.
  3. La lecture utilise la synthèse vocale du navigateur (Web Speech) avec deux voix distinctes pour incarner les intervenants.
ⓘ

Tout se passe sur la machine : le texte est généré par votre moteur LLM local et lu par les voix système. Aucun envoi vers un service externe.

Prise en main

Mode application

Lumen dans une vraie fenêtre, façon ChatGPT : la discussion au centre, toutes vos apps dans la barre latérale.

Au lancement, Lumen propose trois modes : la barre flottante, le mode application et Lumen Desktop. Le choix peut être mémorisé ; le bouton Changer de mode le rouvre à tout moment.

La barre latérale

  • Discussions : l'historique, rangé par dossiers et projets, avec recherche.
  • Organisation, Création, Recherche, Communication, Audio : les apps installées, par famille.
  • Productivité : Documents, Présentations, Notes, PDF, Relia, la Calculatrice et les outils de données (tables, analyse, ETL…).
  • Agents & automatisations : Automatisations, Fluxo, Agents, Mémoire et Diagnostic.
  • Fichiers : la Bibliothèque de vos sandboxes.

Le compositeur

Le sélecteur de mode reste visible sous le champ de saisie : Chat, Documents (réponses tirées de votre base de connaissances indexée, avec sources), Routeur, Outils, Documentation ou un workflow Fluxo. Les mentions @ (outils) et # (documents) marchent comme dans la barre.

Quand l'assistant a besoin d'une app (exécuter du Python, créer une note, afficher une carte…), il l'ouvre en coulisse dans sa vue, sans quitter la discussion. ⌘B masque le panneau latéral.

Diagnostic

Comprendre ce que fait l'IA : traces des modèles, réponses orchestrées et Profiler, réunis en une app.

  • Traces des modèles : chaque appel (app, modèle, durée, jetons, prompt et réponse).

Nettoyer les journaux

Le bouton Nettoyer les journaux… affiche la taille de chaque journal et efface au choix : traces des modèles, réponses orchestrées, journal des fenêtres (erreurs), journaux des serveurs IA (llama.cpp, Bonsai…) et statistiques d'utilisation. Aucune donnée personnelle (discussions, documents, réglages) n'est touchée.

Calculatrice

Calculatrice scientifique, statistiques et conversions d'unités — le même moteur que l'outil de calcul de l'assistant.

  • Scientifique : trigonométrie (degrés ou radians, touche 2nd pour les réciproques), puissances, racines, logarithmes, factorielle, combinaisons, constantes π, e, φ.
  • Saisie au clavier : Entrée calcule, Échap efface, ↑ rappelle le dernier calcul ; « ans » reprend le résultat précédent. La virgule décimale française est acceptée.
  • Statistiques : moyenne, médiane, quartiles, variance et écart-type (population et échantillon), mode.
  • Conversions : longueurs, masses, durées, aires, volumes, vitesses, énergie, puissance, pression, données, angles, températures.

Dans Études, la calculatrice est disponible en vue dédiée et en panneau d'appoint (bouton en bas à droite), utile pendant un quiz ou une correction.

L'assistant dispose des outils calculate, statistics et convert_units : il calcule exactement au lieu d'estimer de tête.

Toutes les consignes envoyées aux modèles, modifiables et restaurables.
