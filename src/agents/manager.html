Une date programme l'exécution : l'agent ne voit la tâche qu'à partir de ce jour. Sans date = disponible tout de suite.

L'agent travaille au déclenchement (un tick = une tâche traitée). Choisis un rythme, ou passe en « Expression » pour écrire n'importe quel CRON.

Espace fichiers isolé où l'agent écrit ses résultats (dossier journal/). Bureau verrouillé, le choix demande le mot de passe de session.

Les capacités natives de l'application : maison connectée, recherche web, documents, bases de données, mémoire, rappels, messagerie. Rien n'est exposé tant que ce n'est pas coché. Les outils marqués « sortie » quittent la machine et demandent une approbation.

Seuls les connecteurs cochés entrent dans le prompt de cet agent. Un connecteur activé dans les Paramètres mais non coché lui reste invisible.

Le « system prompt » de l'agent : il guide la boucle et le choix des skills.

Réglages de l'agent (ville, thèmes, horaires…) plutôt qu'un long texte. Cite-les dans l'instruction avec {{nom}} ; elles sont de toute façon transmises à l'agent.

Distillées depuis ses réussites et ses échecs, puis injectées dans son prompt — à condition que l'apprentissage soit actif (onglet Autonomie).

Propre à cet agent : un agent peut tourner en local pendant qu'un autre passe par le cloud.

Doit supporter les outils (qwen2.5, llama3.1…).

Serveur propre à cet agent (sinon celui des réglages Lumen).

Plus grande = plus de mémoire utilisée.

Voix de ses réponses lues à voix haute (barre de Lumen, bouton 🔊). Les voix locales s'installent dans Réglages › Voix.

Les effets sensibles sont contrôlés côté Rust avant l'exécution de l'outil. Une confirmation reprend le run au même endroit.

Au-delà, la boucle se met en pause et escalade vers toi (Messagerie).

Tokens (prompt + générés) cumulés sur la tâche. Dépassé = escalade.

Les tâches déjà exécutées deviennent des cas notés. Sans eux, « meilleur » ne veut rien dire — c'est ce corpus qui départage deux versions.

Trois variantes sont écrites, notées sur les cas, et l'actuelle n'est remplacée que si l'une la dépasse. L'ancienne reste restaurable.

Taux de succès réel par version. Une version dont le taux retombe sous la précédente est automatiquement révoquée.
